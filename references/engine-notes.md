# 三阶段 A 股投资策略引擎

一套可重复执行的选股流程：**筛选 → 精确判断 → 执行计划**。
所有判断基于取数缓存里的公开数据，每个数字都能追溯来源，同一份数据必得同一个结论。

> 不构成投资建议。不接券商下单接口。历史数据推不出未来。

---

## 一、为什么这样设计

三个原则，每个都能对应到真实踩过的坑：

**1. 先算便宜，再算贵。** 五千多只股票逐只取财务数据要几十分钟，但「市值够大、成交够活跃」
用一次全市场快照就能砍掉八成。所以漏斗刻意设计成**越往后越贵**：
L0 股票池（1 次调用）→ L1 规模流动性（0 次额外调用）→ L2 财务（每只 1 次）→ L3 估值（0 次）。

**2. 先否决，再打分。** 打分制最大的问题是「高分掩盖致命缺陷」——一家公司 ROE 再高，
如果利润三年不落袋成现金，也不该买。所以否决项独立于分数，一旦触发直接回避。

**3. 先说清什么情况下认错，再说买。** 给不出可证伪条件的论点不是论点。
每只股票必须写明：什么事实出现就说明买入逻辑破了。

## 四、阶段四：周度模拟盘（paper.py / weekly.py / paper_exec.py）

> 前三阶段（筛选/精确判断/执行计划）的判据、公式与执行细节**唯一出处是 `SKILL.md` §1**，本文件不再复述；这里只写阶段四的设计与依据。

**动机**：前三阶段每跑一次只回答「今天买什么」，回答不了「上周买的现在怎么样、要不要卖、这套策略到底能不能挣钱」。
第四阶段是**账本 + 定时决策 + 可结算绩效**，先把真钱之前的验证闭环建起来。

**分层**：

| 模块 | 职责 | 不做什么 |
|---|---|---|
| `paper.py` | 账本：持仓/现金/成交/挂单/净值；撮合、费用、止损、绩效（纯标准库） | 不取数、不选股、不做任何策略判断 |
| `weekly.py` | 决策日编排：跑三阶段 → 目标整手数 → 与账本差额 → 挂单 → 写周报 | 不自己算分、不自己定价位 |
| `paper_exec.py` | 手动补跑/执行日工具：把生效挂单按 `--date` 当日开盘/最低价撮合 → 结算 → 报净值（模拟盘不做定时任务） | 不改目标、不撤挂单 |
| `review.py` | 记分卡：读账本算净值/超额/回撤/胜率/盈亏比/费用占比，三态判「样本不足/未达标/暂达标」 | 只读、不改规则、不下结论外的建议 |
| `doctor.py` | 体检：环境（Python/取数接口层/pandas/目录可写）、账本结构与口径、`out/` 属于哪个本金、缓存与漏斗、账本摘要 | 只读、不取数、不下单、不改账本 |
| `report_html.py` | 渲染自包含 HTML：周报（一句话结论/KPI/市场与仓位预算/本期分析/购买策略/本期订单/未来计划/与上期变化）、月报（账本表现/逐笔成交/归因/拆账/记分卡判定/下月计划） | 只读，不重算策略、不改账本、不联网 |
| `monthly.py` | 月度复盘：按自然月汇总账本的收益/基准/超额/回撤/费用/已实现/浮动/现金利息/权益层盈亏/可投资本，输出 md + HTML | 只读、不改规则、不自动调阈值 |

**关键设计决定**：

1. **决策日与成交日分离（定稿口径 `next_open`）**：`PAPER.fill_price="next_open"`——**决策每周一次**：
   周六 20:00 决策用**交易日 19:00 由 `stock prefetch` 统一取数**后的周五收盘数据（周六不重取，周末行情不变；周末公告/新闻由事件面采），卖出价为**下周一开盘价**、买入为**限价条件单**（见下条）。理由：开盘价是卖出真实能成交的价；买入用限价才不会把成本抬到计划价之上。
   （回测按旧的双决策日口径跑，与现行每周一次的差异已在回测报告标题注明。）
   `effective_from` = 决策日之后第一个交易日，撮合只取该日及以后的开盘价，杜绝未来函数。
   `decision_close`（`paper.execute_at_close` 按决策日收盘价成交）只是可选分支，**不是**线上口径。
2. **三类订单**：`sell_open`（减仓/清仓，次日开盘价）、`buy_limit`（**全部买入**：新开仓三批 + 加仓；跌到限价才买，开盘不高于限价按开盘价成交、否则盘中最低价触及限价按限价成交，`limit_expire_days` 个交易日后失效；买入只生成 `buy_limit`；`buy_open` 仅兼容旧账本）、
   `sell_stop`（GTC 条件止损，盘中触发；跳空时按开盘价，可能比止损价更差）。
3. **差额再平衡而不是全量重建**：每周只下「目标 − 持仓 − 已挂未成交」的差额；
   偏差在 30% 以内且单笔 <300 元时不交易，避免每周来回摩擦把本金磨掉。
4. **止损单常驻**：持有就有 GTC 条件止损，两次决策之间盘中跌破也能卖；移动止损上移时同步更新该单的限价与股数。
5. **ETF 套 -15% 初始止损（锚定实际成交成本 ×0.85）**：ETF 没有估值锚（没有合理 PE），阶段二给不出止估价，统一套 `EXEC.stop_loss_pct` 生成计划占位价，成交后按成本重设。
6. **账本是唯一事实来源**：`state_*.json` 记录每笔成交、费用、已实现/浮动盈亏、现金层利息流水、每日净值；
   `out/paper/weekly_*.md` 与 `orders_*.csv` 都是从账本和阶段三产物生成的**输出**，不能反过来手改。
7. **调仓模式（账本统一 `regime_change`）**：只在**市场状态（进攻/平衡/防守）变化**时按当期目标组合重建，其余时间不动，
   只保留 ①止损/组合熔断 ②超市场状态 cap 的兜底砍仓。依据是 PIT 全集历史回放（[历史]，完整数字与显著性见 §七）：
   同口径下 `regime_change + 止损` 是历史最优变体，`incremental`（事件驱动）与 `once`（只建仓一次）当年收益为负或接近零，
   `full`（每周按目标全额重建）年化转负——`incremental`/`once` 保留为**可选开关**，改回须在 §六 登记理由。
   `weekly.py` 把本次为什么动/不动写进周报「三、本期动作与理由」（`regime_change：市场状态 X，重建` 或 `与上期相同 → 本期不调仓`）。
8. **模拟盘阶段不设执行任务**：没有真实资金，不需要布置执行任务。
   所以定时任务只有**每周六 20:00 决策**（外加每月 1 日 22:00 复盘）与**交易日 19:00 统一取数（`stock prefetch`，Windows 计划任务）+ 20:00 巡检（DSH 会话，提示词底稿 `prompts/daily_patrol.md`，每周可加附加任务，见 SKILL §8.1.2）**；决策日**不取数**，行情数据来自交易日 19:00 统一取数后的产物；
   真钱阶段的执行窗口是成交日（下周一）09:35–10:00，
   现在不建任务。模拟盘的成交不需要盘中操作——`effective_from` 卡死在下个交易日，账本在下一次决策时
   按订单类型撮合：**卖出**在下一个交易日按开盘价成交、**买入**按限价条件单触价成交，然后结算；
   `paper_exec.py` 退化为**手动补跑工具**（`--date <交易日>`，`next_open` 口径，可回溯任意一天）。
   将来接券商，只需把执行日 09:35 起的 agent 里「模拟成交」换成券商回报，账本逻辑不动。
9. **止损单的两条硬不变量**：
   ①每个持仓只留一张 `sell_stop`、覆盖全部股数——加仓成交会激活括号止损（只覆盖新增股数），
   旧 GTC 仍按加仓前股数挂着，同一持仓两张单合计超过持仓；跌破时第二张会在 `apply_fill`
   抛「持仓不足」把整次决策打挂。`weekly.py` 每次决策先调 `paper.consolidate_stop_orders()`
   合并（取价高者、只上移、撤多余单）。
   ②止损单的**价格/股数一改，`effective_from` 必须顺延到下一交易日**：撮合按日线逐日回放
   `effective_from..as_of` 的窗口，若沿用旧生效日，新上移的止损价会被拿去重放过去两周的
   日线、凭空补一笔历史成交（2026-11-21 实测：601058 止损 11-20 从 8.17 上移到 11.623，
   旧生效日 11-02 会在 11-02 以 11.13「补卖」——未来函数）。`paper.stop_orders()` 更新既有
   GTC 时已自动顺延；一次性账本修复见 `out/team/pending_changes.md` 当日条目。

**绩效口径**（回答「能不能挣钱」用，见 §七 验证记录）：验收按两条线——
①**净利润 ≥ 0**：净利润 = 账户累计收益 − **token 实花**（`out/budget.json` 该账本累计 `spent_cny`，真实扣费流水）；
②**净年化 > 用户实际一年期定存 1.3%**（`config.PERF["deposit_rate"]=0.013`，与评分保底线 `SCORE["floor_rate"]` 同一口径，带 `as_of`/`source`；1 年期国债 1.18% 只作市场参照）。
且**必须同时报账户收益、token 实花、净利润、净收益率四项**——降基准会让达标显得更容易，只看百分比是自欺。
年度计提（`config.token_cost_annual()`：5 万 150 元/年，其他本金按 0.3%）**只作次年预算档位**，不计入净利润；
奖励评估期 = 基准日 2026-10-28 + 12 个月 = **2027-10-30**，此前 reward 一律 0。
旧指标（净值/累计收益、年化、最大回撤、胜率、盈亏比、累计费用占比、同期沪深300 与超额）降为诊断，仍要报。
最小观察窗 12 周且成交 ≥10 笔，不足就说「样本不足」。

**token 三类计价（实现依据，仅插件内部使用）**：价格表不是自拟，照抄本机插件
`<dsh-whale-widget 插件>\lib\index.js`（`BASE_PRICE` / `PRO_PRICE` /
`PEAK_HOURS` / `HOLIDAY_VALLEY` / `WEEKEND_VALLEY_FROM_SEC` / `HOLIDAY_VALLEY_FROM_SEC`）：
`cost = cacheRead/1e6×hit + input/1e6×miss + output/1e6×out`（`input` = cache miss；reasoning 已含在 output；技能直接取插件已算好的 `events[].cost`，不自行核算）。
**计费只认实扣（周期结算）**：`billing.py --task-end` 在**下一次决策会话第 2 步**执行（补记上一周期：上一次决策会话 + 期间巡检）读小鲸鱼记账账本 `events[].cost` 在「上次结算终点 → 现在」区间的累计，结算后推进终点（`out/team/billing_cycle.json`）；不需要 `--task-begin`（可选，仅用于单独量某次窗口）；账户余额观测（`accounting` 的 `debitUnits`）只作参考字段 `account_delta_cny`；区间内所有本机消耗都计入，缺记录记 0 不估算。
不做 token 单价公式核算、不做估算：只取插件的 `events[].cost`。

## 五、执行阈值

阈值唯一出处是 `scripts/config.py`（改阈值只改那一个文件），规则执行口径以 `SKILL.md` §4 / §8.3 为准。
下表**只列容易被误读、且 SKILL 正文不重复展开的执行项**，数值仍以 config 为准：

| 项目 | 数值 | 含义 |
|---|---|---|
| 单票上限 | 10% | 任何一只股票不超过总资金 10% |
| 行业上限 | 25% | 同一行业合计不超过 25% |
| 总敞口上限 | 市场状态 35%/60%/80% | 防守 35%、中性 60%、进攻 80%；机会不足时允许低于上限 |
| 单票止损 | 初始 -15% 硬止损（锚定**实际成交成本**） | 无条件执行；`paper.apply_fill` 在成交时按「买入费用摊入后的 `cost_basis` ×0.85」写入止损，括号止损单同步重锚。计划里的 `buy_price×0.85` 只是下单参考/占位价，**不是成交后的止损**——实盘按市价成交通常比安全边际价贵 10%~20%，照抄会把 -15% 放大成 -23%~-29%。已有持仓不回溯改；加仓不重设既有止损（上移只由 2.5×ATR 跟踪负责）。浮盈 >10% 后改用 `EXEC.atr_mult` 跟踪，只上移（`EXEC.stop_loss_pct` / `EXEC.atr_mult` / `EXEC.trailing_start`；规则正文见 `SKILL.md` §8.3） |
| 组合回撤熔断 | -15% | **全部卖出（清仓）** + 当周不新建仓（`EXEC.portfolio_dd_halt`；规则正文见 `SKILL.md` §8.3） |
| 时间止损 | 12 个月 | `patrol.py` **只告警**（kind=时间止损），是否退出由决策日/Lead 判断，不自动清仓（`EXEC.time_stop_months`；见 `SKILL.md` §8.3） |
| 现金层利率 | 以 `config.cash_rates()` 为准（单一来源：工作日巡检（DSH 20:00 会话跑 patrol.py）`rates.py` 实测——**货基每天刷、逆回购每周五刷**；落 `WORK_DIR/cash_rates_live.json`（本部署 = `<本技能目录>\stock\data\invest\cash_rates_live.json`），超 2 天失效回落常数） | **文档与汇报不得写死具体利率，也不得用没扣佣金的毛数**；逆回购净 = 毛 − 年化佣金（7/14/28 天期 0.26%/本金·年；1 天期日滚 0.25%），现金侧用其 7 日年化。默认分工：挂单资金朝朝宝（T+0）、建仓弹药（权益上限−现有场内权益）也留朝朝宝/券商现金（周六决策、周一生效，场外货基周末不能赎回）、观望资金半流动性货基池；逆回购不建常驻仓，只在 `repo_pulse.py` 判 GO 的脉冲日打（§5.7c，期限按净 %-天取最大） |

「日亏停手 / 周亏减仓 / 连亏停手」三条从未接线（无阈值、无代码），不作为规则，已从正文与计划书删除。

## 六、规则变更怎么登记

**文档里不维护变更日志**；全部历史改动见 git 提交历史。

改阈值/规则的三条纪律：

1. 先说明依据是**分布统计或复盘结论**，不是某只标的的输赢；
2. 一个改动一次提交，commit message 必须写清：原值 → 新值 → 依据（含日期与数据口径）；
3. 同时更新 config.py 注释与引用该阈值的文档段落（SKILL.md §4 阈值纪律）。

不允许边跑边调，也不允许只改代码不改说明。

## 八、已知限制

1. **不含机构与预期数据**：没有机构持仓、分析师一致预期、业绩预告、北向资金、股吧情绪。
   这些接口要么收费、要么本机被拦截。
2. **财务数据滞后**：年报通常次年 4 月才出，本引擎用「最近一期」算增速，
   所以最新成长性可能滞后一个季度到半年。
3. **不含港股美股**：只做 A 股与国内 ETF。
4. **不做择时**：市场状态只影响仓位上限，不做「预测明天涨跌」。
5. **回测只覆盖 ETF 兜底层**：`backtest.py` 能回放 ETF 承接层，
   但个股层**不能**回测——财务指标与估值分位没有 point-in-time 数据，用「现在知道的基本面」去回放
   「当年的选股」就是前视偏差。要看选股层表现，只能靠前向模拟盘（阶段四）往后攒真实数据，
   而且本金要 ≥5 万才买得起一手。
6. **东财系接口不可用**：`*_em` 全系列在本机被网络层拦截，只能走新浪/中证/百度。
7. **场外 R2 层用影子账记账**：`otc_book.py` 按「提交日的下一交易日累计净值」成交、T+1 确认，市值 = 投入 ×（当日累计净值 / 买入日累计净值），赎回费按持有天数取实测档；`paper.settle()` 的净值已含场外市值，`investable_capital()` 的再投资基数含场外已实现收益。仍有两个边界：①场外没有 point-in-time 数据，**不做历史回放**；②账本与真实 APP 确认存在 1–2 个交易日的时差。**首次补建例外**：`regime_change` 模式下状态未变就不调仓，但影子账上线前的旧账本没有场外持仓/在挂单/历史成交，这条腿会一直空着——因此对「三无」账本允许按当前计划目标补建一次（`otc_book.bootstrap_needed` + `weekly.otc_allow_rebalance`），补建成交后即永久停止触发；这不是调仓，也不改变 weekly 的「状态未变不动」口径。另：HTML 周报新增「九、场外债券基金（R2 层影子账）」小节，订单表也列场外申购单（此前只在 md/CSV 里可见）。
8. **场外基金池没有规模硬门槛**：`fund_purchase_em` 不直接给规模，规模补查走 `fund_individual_basic_info_xq`（best-effort，失败不阻断，漏斗里记 `scale_unavailable`）→ 清盘风险主要靠「日累计限定金额 / 历史 ≥750 交易日 / 3 年回撤筛」兜，不是规模门槛兜。**全量实测：池内 523/1,087 只的规模没校验到**（`xq` 规模接口取不到，按设计 fail-open 放行，`L7_scale_unavailable = 523`）；其余 564 只已校验、无一只被 1 亿门槛淘汰（`L7_scale_small = 0`）。当期数字以 `out/stage1_otc_funnel.json` 为准。这是明确的已知缺口，不是已经解决的问题。
9. **逆回购期限与利率假设**：**现行口径逆回购 = 投资层脉冲择时**——观望资金在货基池，只有 `repo_pulse.py` 判 GO 的脉冲日才打一笔；**池子只装「观望资金」**：`paper.cash_yield_plan()` 先扣在途逆回购与场外申购占款，再扣 **T+0 保留 = max(建仓弹药, 场内挂单冻结)**（建仓弹药 = max(0, 权益上限 − 现有场内权益)；在挂买单冻结的钱已含在弹药里，两者取较大者、不重复扣），权益上限取调用参数 `cap_amount` > 账本 `meta["equity_cap"]` > 0，剩下的才给 `cash_sleeve` 切片——因为决策在周六、买单周一生效，而场外货基周末不能赎回（普通赎回 T+1），弹药必须周一在券商账户；**期限规则（「尽量争取最大利润」，`choose_term()`）**：按同一窗口**净 %-天**（含手续费、按实际占款天数计息）取最大——1 天期与 7 天期自动比较，14 天期只在给了 `--rate14` 时比较，28 天期不自动推荐；锁定期内可能建仓时 `--need-build` 强制 1 天期。利率由 `rates.py` 实测：`repo` 取 1 天期 GC001/R-001、`repo7` 取 R-007，**货基每天刷、逆回购每周五刷**；14/28 天期沿用 7 天期利率近似（已知简化）。年费率 7/14/28 天期均为 0.26%/本金（1 天期日滚 0.25%）。**回滚口径**：`cash_policy` 改回 `orders_mf_idle_repo7` 即恢复「观望资金买 7 天以上逆回购、每周一一次、按金额分档（<8,000→7 天、8,000–20,000→14 天、≥20,000→28 天）」。
10. **生息类逐日结算（硬规则，禁止「年化 × 天数」偷懒）**：①朝朝宝按 `cash_rates_history.jsonl` 的**当日利率**逐日计息，当日缺失沿用之前最近一天，不拿整段窗口的年化一把算；②半流动性货基池按**逐日万份收益**入账（利息 = Σ万份收益 × 金额 / 10000，每日收益再投入）——90 天实得年化只用于选基排序；③某只整段取不到万份收益时该笔**不计息并告警**（`basis="缺数未计"`），**绝不**回落「年化 × 天数」估算；④**持仓以账本 `sleeve_lots` 为准**：首次计息把实际切分（代码/金额/数据日）写入账本，之后逐日万份收益都按这份持仓算；只有排行刷新（data_date 变化）才换仓。排行过期或排行文件读不到时沿用 `sleeve_lots` 继续计息，不整笔退回朝朝宝；新配置仍按 `max_stale_days=5` fail-closed。排行不可用时 `mf_amt` 要扣掉 sleeve 金额，避免与朝朝宝重复计息。⑤逆回购按 lot 成交锁定的利率结算（成交即固定，属逐日等值）；回测用固定利率逐日等值，历史无日频利率序列。
11. **`determinism.py` 两遍必须在同一自然日内跑完**：`datasource._cache_file()` 用 `today()` 命名缓存，跨 0 点第二遍全冷，费率请求并发超时会让 1,087 只掉到 1,039 只（实测）——跨日重跑前先确认两遍都在同一天内。
12. **年度结算（每年 1 月 1 日）的五条不变量**：①**档位按等价年化净收益率**定（`score.evaluate(days=…)`，不足一年按 `(1+净收益率)^(365/天数)−1` 折算），**奖励 = 当年净利润 × 档位比例**，当年净利润 = 当年毛利 − 当年 token 实花（token 按 `out/budget.json` 的 runs 落在该自然年的 cost 求和）；②奖励（评估期后>0）**从账户现金划出**，**本金重置为「年末净值 − 奖励」**，下一年收益率以剩余净值为起点；③总收益按 `meta.cum_index *= (1+当年收益)` **跨年链式累计**（`paper.portfolio` 的 total_return = cum_index × nav / 本金 − 1；`paper.stats` 同口径）；④`meta.annual_baseline` 在结算时重设为当时的已实现盈利/现金利息基线，`investable_capital()` 只把基线之后的已实现盈利计入可投资本，避免同一笔盈利重复放大仓位；⑤记录写 `meta.annual_settlements.<年>`、结算前 `paper.backup_state()`、同年**幂等**不重复入账；重渲染年报用 `--no-settle`。奖励划出造成的净值一次性回落（约 奖励/净值）属资金流出，不是亏损，也不触发熔断。
13. **选股评分面板只记录、不参与选股**：每周决策由 `weekly.py` 调 `score_panel.archive(data_as_of, basket=…)` 把 judge 的候选四维分数写到 `out/archive/scoring/<数据日>.csv`（同日期覆盖=幂等，失败只打印、不影响账本/订单）。年报的「选股评分体检」用 `score_panel.health(年)`：分维度 IC（分数与前向超额的秩相关）、五分组差（最高组减最低组）、买入区/观察/回避的前向超额与跑赢比例、子项覆盖率。**结论门槛**：面板 <26 周或 <30 条观测 → 只能写「样本不足，维持现状」；达标也只作参考，任何分值/子项改动必须影子 12 个月、且只能在下一年 1 月 1 日生效。评分是排序工具，验收看样本外分组差，不看当期买到的那几只赚没赚。前向超额以沪深300 为基准、按交易日历对齐（1/3/6/12 个月），价格缺失记为未观测，不补值。

## 六、历史退市 / ST 口径

- 数据：`ds.fetch_stock_basic()`（上市日/退市日）、`ds.fetch_delisted()`（约 300 只退市股）、`ds.fetch_st_intervals(code)`（baostock 日线 isST 区间）、`pit.listed_asof(day)`（那天仍在市）。
- 用法：筛选是当日口径，用当日简称名单即可；回测要复原历史可选池，必须用 `listed_asof(day)` ∩ `pit.index_members(index, day)`，否则「后来退市的票」会整只消失（幸存者偏差）。
- 已知边界：baostock 基础信息含指数（类型字段区分）；北交所代码 baostock 不支持；退市日当天仍按最后成交价清算（回测里不是按归零）。
- 持仓侧处置：巡检 `patrol.check_holdings_risk` 用当日简称名单比对持仓，命中 ST/*ST/退市整理报高危；决策日 `weekly.py` 把命中标的从目标池剔除并调 `paper.risk_exit_orders` 下一交易日开盘清仓，与止损/熔断同级、不受「状态未变不调仓」限制，当周不回补。卖不掉（连续跌停/停牌）时账本按最后收盘估值、不虚构卖出成交。
- 一字板撮合闸门：`paper._board_locked(bar, prev_close)` 用「high==low 且涨跌幅正好是一档板（5/10/20/30%）」识别封死板；`resolve_orders` 跳过跌停封死日的卖单、涨停封死日的买单，顺延到打开日。局限：真实封单量与排队顺序无法从日线还原，同一板价下是否成交只能用「是否有区间」近似。
