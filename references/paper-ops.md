# 阶段四 paper 操作细节（对应 SKILL.md §8.2–8.12）

> 规则、阈值、口径以本文件与 `scripts/config.py` 为准；`SKILL.md` §8 只留标题与指针。

### 8.2 两条命令各自管什么

- `weekly.py`：读 `stage3_plan.json` → 转成「目标整手数」→ 与账本持仓做差额 → 生成四类单：
  ①卖出单（`sell_open`，减仓/清仓，按下一交易日开盘价成交）；
  ②买入单（`buy_limit`，**新开仓三批 + 加仓全部是限价条件单**，跌到限价才买，`limit_expire_days` 个交易日后不成交自动失效；ETF 默认单批一次买入，不拆条件单；撮合规则见 `paper.py` 的 `resolve_orders`）；
  ③条件止损单（`sell_stop`，GTC；每次决策按当日收盘价判断是否跌破，跌破就在下一交易日开盘卖出，否则维持/上移触发价）。
  **每个持仓只保留一张止损单**：每次决策先 `paper.consolidate_stop_orders()` 把「加仓括号单 + 既有 GTC」合并成一张、覆盖全部股数、取价高者（只上移），否则跌破时第二张会因持仓不足把决策打挂；**止损价/股数改过后生效日顺延到下一交易日**（不用新价回放历史，防未来函数）。同时结算净值、更新移动止损（浮盈 >10% 后才启用，只上移）。
- `paper_exec.py`：**巡检执行工具**（每日 20:00 巡检第 2 步）。把「生效日 ≤ `--date`」的挂单按当天开盘/最低价撮合（`next_open` 口径），记成交与费用，打印净值与仓位；**只撮合已触发的单**（止损跌破触发价/跳空、买入限价触价），未触发与未生效的一律不动，故不会替人调仓。`--dry-run` 只预览不落账。补跑或提前看成交：`paper_exec.py --ledger 50k --date <交易日>`。
- `--ledger 50k`：本金/档位/账本路径从 `config.PAPER["ledgers"]` 取（本部署只有 50k 一本）；输出文件名 `weekly_{date}.md`。
- **调仓模式按账本取**（`config.PAPER["ledgers"][账本]["rebalance_mode"]`），**默认 `regime_change`**：
  - 只在**市场状态（进攻/平衡/防守）变化**时按当期目标组合重建（重算整手数、订单、止损），其余时间**不因排名变化或每周决策换仓**，只保留 GTC 止损与组合熔断；超市场状态上限的砍仓只作风控兜底。
  - 依据：PIT 全集与各模式对比见 `references/engine-notes.md` §七（`incremental`、`once` 均低于 `regime_change`）。
  - 开关：`incremental`（事件驱动：判坏/超 cap/有新目标/偏离带才动）与 `once`（只建仓一次）保留在代码里，切换须走一次 git 提交并写明理由。
  `weekly.py` 会在周报「二、本期操作」逐条写清本期为什么动/不动（`regime_change：市场状态 X，重建` 或 `与上期相同 → 本期不调仓`），引言行显示该账本的调仓模式。

### 8.3 账本口径（被问到必须能解释）

- **费用**：佣金**万 1**、**最低 5 元/笔**（只在 `config.ACCOUNT` 定义，`config.CAPITAL` 引用，全库唯一出处）；ETF 无过户费、无印花税；股票卖出印花税 0.05%。买入费用摊进成本价，卖出才确认已实现盈亏。成本率 = 5 元 ÷ 单笔金额：单笔 800 元 = 0.63%、2,500 元 = 0.20%、5,000 元 = 0.10%（单边）；**万 1 的追平点是单笔 50,000 元**，5 万本金够不到，故成本率实际只由「5 元 ÷ 单笔金额」决定。**本部署下限**：新开仓/补仓单笔 ≥5,000 元（`PAPER.min_order_value`，买不起按手数降级）、ETF 单批 ≥1,500 元、每月新买 ≤2 次（`PAPER.max_trades_per_month`，只约束增量换手，不约束首次建仓/重建/止损）。**注意「ETF 最小 800 元」是佣金下限口径（单笔 5 元最低佣金），与本部署「ETF 单批 ≥1,500 元」是两条不同规则，别混用**。
- **两道下单闸门（都在 `plan.py`）**：
  - **单笔成本率闸门**：单笔佣金率取 `capital.trade_fee(金额, is_etf).ratio`，超过 `config.CAPITAL["commission_ratio_block"]`（**0.65%** = 5 元 ÷ 800 元 ≈ 0.63% + 整手余量）→ **不建这条腿**，记 `plan["cost_blocked"]`，计划书写「不是买不起，是佣金吃掉太多」。例：sh510050 单笔 **574.40 元 = 单边 0.87%**，`ETF.min_position_value = 800` 只是下限、不构成拦截——参数存在 ≠ 参数生效。
  - **往返成本闸门**：往返 = 买入佣金 + 卖出佣金 + 印花税（股票 0.05%，ETF 免）+ 过户费，比率 > `config.EXEC["max_roundtrip_cost"]`（**0.60%**）→ 不建这条腿。为什么不是 0.50%：单腿 2,000 元时股票往返 0.55%、ETF 0.50%，闸门线必须 ≥ 它，否则 1 手 2,221 元的合规单会被误拦（华润三九 1 手往返 0.5018%）；该拦的是：601058 1,144 元往返 0.93%、sh510050 574.40 元往返 1.74%。
  - **赔率闸门**：赔率 =（目标价 − 计划买价）÷（计划买价 − 止损价），< `config.EXEC["min_risk_reward"]`（**1.5**）→ 不建仓。**按第 1 批限价算，不能按现价算**：同一只华润三九按现价 25.40 买赔率 1.84、按限价 22.21 买 4.29，按现价会把「等回调再买」错判成「追高」。
- **R2 场外「产品持有期」是硬约束，与「不满 90 天不赎回」是两件事**：条款持有期（如「180 天持有期」）管能不能赎，纪律管该不该赎——纪律管不了合同。选池按 `config.RISK.wealth.otc.max_hold_period_days`（**30 天**；一季要能动一次，锁定期就得 ≤ 一季）过滤，解析器 `metrics.hold_period_days()`（`plan.py` 与 `otc.py` 共用一份正则）；下单侧 `otc_book.target_orders()` 对未到持有期的持仓**不生成赎回单**（含「不在目标里 → 全额赎回」与「减仓」两条路径）。例：2026-11-02 买入 018193 建信鑫弘「180 天持有期」C，2,300 元锁到 2027-05-01。
- **净值和绩效**：`stats()` 给胜率/盈亏比/已实现/浮动/累计费用/最大回撤/年化；年化在天数 <30 时标「样本不足仅供参考」。**相对基准**：沪深300（`config.PAPER["bench_index"]`），报「同期沪深300 / 超额」，超额才是「这套策略有没有用」的证据。
- **止损**：初始止损一律 = **实际成交成本 ×0.85**（`EXEC.initial_stop_pct`=-15%，买入费用摊入成本），由 `paper.apply_fill` 成交时写入、括号止损单同步重锚；ETF 无估值锚、个股计划里的 `buy_price×0.85` 只是下单参考价，**不许当成交后的止损**。已有持仓的止损不回溯修改（只对新开仓/重建生效）。
- **持仓被实施风险警示（ST/*ST/退市整理）**：巡检每天用交易所**当前简称**比对持仓（`patrol.check_holdings_risk`，简称含 `ST` 或「退」即命中，报高危）；决策日 `weekly.py` 用同一份名单把命中标的从目标池剔除，并调 `paper.risk_exit_orders()` 下一交易日开盘**全部卖出**——与止损/熔断同级，**不受「状态未变不调仓」「熔断后不建仓」「每月新买 ≤2 次」限制**；清仓当周不回补。连续跌停/停牌卖不出时，账本按最后收盘价估值、**不虚构卖出成交**，成交价只在真正撮合后写入，汇报如实说明「未能卖出」。
- **熔断与时间止损**：组合回撤 `EXEC.portfolio_dd_halt`（-15%）触发后**全部卖出（清仓）、当周不新建仓**；时间止损 `EXEC.time_stop_months`（12 个月）只由 `patrol.py` 告警，是否退出由决策日/Lead 判断，**不自动清仓**。「日亏停手 / 周亏减仓 / 连亏停手」无阈值、无代码，不作规则引用。
- **分红送转（除权日实际入账）**：除权日由 `patrol.py` / `weekly.py` 调 `dividends.map_for()` + `paper.apply_dividends()` 写入——现金按**税后**（持股 ≥1 年 0%、1 月–1 年 10%、<1 月 20%，天数 = `opened_at` 到除权日）加进 `cash`；送转按每 10 股比例增股、`cost_basis` 按总成本摊薄，**止损价不动**（分红不是亏损）；幂等靠 `meta.dividend_paid`（同一除权日只入一次）；除权日 ≤ 建仓日不派（没赶上股权登记日）。ETF 走累计净值，不走这条。数据源 = 东财数据中心 `RPT_SHAREBONUS_DET`（`ds.fetch_dividends`），与同花顺复权因子交叉校验。
- **仓位**：总敞口永远受市场状态上限约束（防守 35%），档位只在 cap 之下选。
- **现金层计息**（现金不是 0 收益）：每次决策/结算按「上次计息日到今天」自然日**逐日**计息，写一条 `cash_yield` 事件（可追溯）。**禁止「年化 × 天数」一把算**：朝朝宝按 `cash_rates_history.jsonl` 的**当日利率**（当日缺失沿用之前最近一天，不回头用今天）；半流动性货基池按**逐日万份收益**入账（利息 = Σ万份收益 × 金额 / 10000，每日收益再投入；选基仍按 90 天实得年化，只用于排序）；某只整段取不到万份收益 → 该笔**不计息并告警**，绝不回落年化估算。**事件文案**：`cash_yield` 写「实得金额 + 实得年化」（= 实收利息 ÷ 本金 ÷ 天数 × 365），90 天实得年化与货基池中位数只能放括号注明「选基口径、不是计息利率」，**不许写成计息利率**（如 `@1.30%` / `@1.1%` 会被误读成按此计息）。**持仓以账本为准**：首次计息把实际切分写入 `sleeve_lots`（代码/金额/数据日），之后按此算；排行刷新才换仓，排行过期/读不到沿用既有持仓，不整笔退回朝朝宝、不按 1.06% 重算。**两个基数分开**：朝朝宝基数 = 现金 − 2% 缓冲（T+0，挂单的钱也计息）；逆回购基数 = 观望资金 = 现金 − 挂单/场外申购占款 − 2% 缓冲 − **建仓弹药（权益上限−现有场内权益）** − 在途逆回购本金（锁 7–28 天）；在途本金已按 repo 利率计息，不重复计朝朝宝利息；超上限由 `paper.repo_cap()` 自动收敛并写 `warn`。按 1,000 元整手进逆回购、零头留朝朝宝（净口径见 §8.4）。**挂单的钱照常计息**——逆回购 T+1 到期、开盘前资金已可用。`config.cash_rates()` 是唯一访问器，`PAPER["cash_yield"]` 只留操作日与期限费率、不重复存利率。
- **场外 R2 腿的记账边界（影子账）**：场外持仓由 `otc_book.py` 单独记账，`paper.py` 不管它，但 `paper.settle()` 的净值会把场外市值加进来，`investable_capital()` 的再投资基数也含场外已实现收益。三条硬规则：①**绝不编价格**——没有当日累计净值就保持 pending，宁可净值少算也不虚构；②**申购费按基金实际费率扣**（`fee_pct`），赎回费按持有天数取实测档（不足 90 天按最严档）；③**分红默认红利再投**（累计净值已含分红），市值只用累计净值比，不单独加分红。汇报时账本净值与周报「场外合计」行必须对得上。**例外：首次补建**——「三无」账本（无场外持仓、无在挂单、无历史场外成交）允许按当前计划目标补建一次，不受 `regime_change`「状态未变不调仓」限制；补建后 `otc_trades` 非空即不再触发，人为赎回清空也不自动追买。
- **净利润口径（所有展示一律照此）**：**净利润 = 账户累计收益（元）− token 实花（元）**；**净收益率 = 净利润 ÷ 本金**。token 实花 = `out/budget.json` 里该账本累计 `spent_cny`（真实扣费流水），**按真实扣费入账**（`config.token_cost_annual()` 只保留预算档位语义，不做利润扣减）。月报、记分卡、`score.py` 评分、T8/T9 报告与汇报必须同时给四项：**账户收益 / token 实花 / 净利润 / 净收益率**——只报毛利视为口径错误。**周报例外：只给净利润 / 净收益率，另单列一行「上周技能花费（实扣）」（展示事实、不参与规则），不展开 token 明细与单价，也不给档位/奖励**（评分只在年报做；净利润仍是扣费后的结果）。
- **工作日巡检简报的计费**：取数由 Windows 任务 `DSH-DailyPatrol` 在 19:00 用纯代码执行（`stock prefetch`，0 token）；账本由 DSH 20:00 巡检会话用 `patrol.py` 计算并出三行简报。**巡检会话按自己的开窗/收口记实扣**——第 1 步 `billing.py --task-begin --ledger 50k --note 每日巡检`、收口第 5 步 `--task-end --note 每日巡检`，按对话时间窗（开窗→收口）的 events 求和入账、两次累计快照差额对账（`estimated=False`，见 §8.4、§5.2）。周报收口时不另记巡检费。
- **奖励评判期**：基准日 2026-10-28 起满 12 个月，即 **2027-10-30 起才评判奖励**；未到期 `reward` 一律 0，文案「评估期未到（2027-10-30 起评判）」。档位阈值不变，输入为净收益率。
- **年报与年度结算（每年 1 月 1 日）**：`monthly.py --month <去年>-12 --annual` 出年报并结算——**档位按等价年化净收益率**定（`score.evaluate(days=...)`：不足一年也按 `(1+净收益率)^(365/天数)−1` 折算，天数 = 年内首个到最后一个净值日），**奖励 = 当年净利润 × 档位比例**（不按年化理论值发钱；当年净利润 = 当年毛利 − 当年 token 实花，token 按 `budget.json` 的 runs 落在该自然年的 cost 求和）。结算动作：奖励（>0）**从账户现金划出**转次年 token 预算；**本金重置为「年末净值 − 奖励」**，下一年收益率以剩余净值为起点；`meta.cum_index *= (1+当年收益)` 做跨年链式累计（`paper.portfolio` 的总收益 = `cum_index × nav / 本金 − 1`），`meta.annual_baseline` 重设已实现盈利基线（避免同一笔盈利重复放大可投资本），记录写 `meta.annual_settlements.<年>`，账本先备份；**幂等**，同年重复运行不重复入账；重渲染用 `--no-settle`。奖励划出会让当月净值出现约 `奖励/净值` 的回落，属资金流出、不是亏损。
- **选股评分体检（年报固定一节）**：每周 `weekly.py` 把 judge 的候选四维评分归档到 `out/archive/scoring/<数据日>.csv`（只记录、不改分值、失败不影响账本）；年报自动读 `score_panel.health(年)`，给分维度 IC、五分组差、买入区/观察/回避的前向超额与命中率。**面板不足 26 周或 30 条观测 → 结论只能是「样本不足，维持现状」**；即便达标，任何分值/子项改动仍须影子 12 个月、且只能在下一年 1 月 1 日生效（评分是排序工具，验收看样本外分组差，不看买到的那几只赚没赚）。
- **不留闲钱**：R2/R3 没有合格机会时，未投出预算**按分工进 R1（挂单资金朝朝宝 + 观望资金半流动性货基池）周转**，只留约 2% 的费用/流动性缓冲（见本节「现金层计息」）。逆回购不建常驻仓，只在 `repo_pulse.py` 判 GO 的脉冲日临时打（§5.7c）。现金层是 R1 配置，不是空仓等待——选股/ETF 买不买、买多少由机会决定，剩下的钱必须生息（净口径与验收线见 §8.4）；只有「等机会」，没有「等现金」的理由。

### 8.4 判断「这套策略能不能挣钱」的口径

验收标准：「不带怂的，只求你的投资收益能赚回你消耗的token钱，剩余赚钱的年利率能大于银行存款就行」。
拆成两条可核对的线（`review.py` 记分卡直接判；超额/回撤只作诊断）+ 一条奖励评判期：

1. **回本线**：**净利润 = 账户累计收益（净值 − 本金）− token 实花 ≥ 0**。token 实花取 `out/budget.json` 该账本累计 `spent_cny`（真实扣费），`review.py --token-cost` 可覆盖实际账单；**不许用年度计提冒充实花**。
2. **跑赢无风险线**：扣掉 token 实花后的**加权年化净收益率** > 用户实际一年期定存利率（`config.PERF["deposit_rate"]`，与评分保底线 `SCORE["floor_rate"]` 同一口径；数值现取）。加权口径 = **季度 50% / 年度 20% / 三年 30%**（不够三年计算到创始）：三个窗口各自先折年化再加权（权重和 = 1，故「加权年化 ≥ 定存」与「加权年化超额 ≥ 0」等价）；窗口默认**滚动**（12 周 / 52 周 / 3 年），不满 12 周的窗口只显示、不判档（`config.PERF.period_weights / period_windows / min_window_days`；实现见 `score.annualize_rate / composite / windows_from_nav / evaluate_multi`，接线见 `review.net_metrics` 的 `multi` 字段）。市场无风险下限参考当日 1 年期国债收益率（`datasource.fetch_cn_treasury_yield()` 现取），仅作参照、不作达标线。**必须同时报账户收益、token 实花、净利润、净收益率四项**：只看百分比就是自欺。
3. **奖励**：评估期 2027-10-30 起才评判（基准日 + 12 个月）；未到期 reward 一律 0，记分卡另起一行写「奖励：未到评估期（2027-10-30 起）」。档位阈值（A ≥4.5% / B+ ≥3.0% / B ≥2.0% / B- ≥1.3% / C ≥0 / D <0）按净收益率判；**年报结算**（每年 1 月 1 日）档位按**等价年化净收益率**、奖励按**当年净利润**，见 §8.3「年报与年度结算」。

**季计价**：日常汇报**主指标 = 本季累计净收益率** = (季末净值 ÷ 季初净值 − 1) − 季内 token 实花 ÷ 本金，对照**季达标线 = 年化达标线 ÷ 4 = 0.325%**（5 万本金 ≈ **162.5 元/季**）。配套常数：**token 季度预算 37.5 元**（年度 150 ÷ 4）。**年化数字一律降为「外推值」脚注、不作达标判据**——27 天样本折算年化会把噪声放大 13 倍。档位**满 12 周（84 天）才出**，不满样本在记分卡印「—」。实现：`config.PERF.period / accept_quarter_rate / token_cost_quarter_cny`、`score.quarter_metrics`、`review.net_metrics` 的 `quarter` 字段、记分卡「本季净收益」列与「本季 … 累计净收益率 vs 季目标（金额）」正文行。护栏：**连续 2 季不达标才算失败**；单季不达标只记录、不改阈值（§8.5）。

**计分时点**：档位/奖励**只在年报（每年 1 月 1 日）判定**（`config.PERF.grade_period="annual"`；`team.py --run-t8 --annual`、`review.py --annual` 才印档位与奖励）。月报只报四项口径与本季进度数字、**不印档位、不判档**（`review.py` 在月报里 `--strict` 不因「未达标」失败）；周决策/巡检本来就不评分。年度结算（奖励从现金划出）同在年报，见 §8.3。

**动态本金**：每月**月报时刻**（1 日 22:00）注资 `config.PERF.dynamic_capital.monthly_injection_cny = 5,000` 元，首次 **2026-12-01**。月报由 `monthly.py` 内 `capital_dyn.settle()` 一次做完三件事：
1. **上月 token 出账**：把**上一个月**的 token 实花从账户现金扣一次（`events.level="token_cost"`，幂等，记 `meta.token_booked`）；此后净值是**净口径**，`收益 = 净值 − 累计投入` 才自洽。
2. **重算各月等价年化**：写 `meta.monthly_rates`。
3. **注资 + 更新本金**：`新本金 = 上月末净值（已扣 token）+ 5,000`，留痕 `meta.capital_history`，记 `events.level="capital_injection"`。

口径三条：
- **月收益率** `r = 月末净值 ÷ 月初净值 − 1`（月初净值取上月最后一个净值点；注资只抬高新月的起点，**不算进上月收益**）。
- **月等价年化** `e = (1+r)^(365 ÷ 该月实际运行天数) − 1`，天数 = 月内首个净值点 → 最后一个净值点（首月只跑了 6 天就按 6 天折，不按 30 天）。
- **年报定档的年化 = 本年（自然年）各月 `e` 的算术平均**（`capital_dyn.year_mean_equiv` → `score.evaluate(annual_rate_override=...)`，`annual_metric="monthly_mean_equiv"`）。

**口径一致性（改口径前必读）**：
- **两个本金不是一个东西**：`meta.capital`（本金）只用于**仓位上限**（单票 10%、行业 25%、权益上限的基数）；累计收益/累计收益率的**分母是「累计投入」**`capital_dyn.contributed_capital` = 初始本金 + Σ注资 − Σ划出。拿 `meta.capital` 当历史分母，每次注资都会把累计收益重置成当月。
- **注资是现金流，不是净值点**：`capital_dyn.inject` 只加 `cash` 与 `meta.capital`，**不改任何已有 nav 行**；算窗口收益时要把窗口内注资从末值减掉（`r = (nav_end − 窗口内注资) / nav_start − 1`），否则 5,000 会被记成当月涨幅。注资归属**报告月的下一个月**（12-01 跑 11 月报 → 12 月到账）。
- **token 只扣一次**：`book_token` 把那月 token 从现金扣掉并同步下调该月最后一根 nav，**净值从此是净口径**；月报/季窗口/多窗口/年报都不得再减一遍（`token_in_nav` 为真时 `token_cost_rate=0`、`net=gross`）。无 token 记录的月份只写 `token_checked`，晚到的 token 还能补扣。
- **年度奖励划出**：`settle_year` 奖励从现金划出时**同步下调年末 nav**，保证 `cash == 末根 nav == meta.capital` 三方一致；`paper.stats/portfolio` 的分母用累计投入、不乘 `cum_index`。
- **月窗口起点 = 上一个月最后一个净值点**：本月只有 1 个净值点也能算等价年化；首月没有上月点时 `days=0`、`equiv=None`（样本不足，列 `missing`）。
- **命令行本金**：`plan.py` / `run.py` / `team.py` 的 `--capital` 不传（0）时自动读账本累计投入——别再写死 `--capital 50000`，注资后 5 万会过期。
- 相关口径还落在：`paper.portfolio/stats/settle`（分母与基准）、`review.net_metrics`（`cap` 与 `equity_pnl`）、`monthly.month_metrics/year_metrics`（窗口收益减注资、token 不二次扣）。年报时刻**先用净值现算一次上一个月（上年 12 月）的 `e` 记入，再取本年所有已运行月份平均**；跨年月份（上年 11 月及更早）只作参考展示、不进平均；某月只有 1 个净值点等样本不足的月份列 `missing`、不计入平均。整段/加权年化只作参考。

**token 计费口径（只认实扣）**：读小鲸鱼记账账本 `events[]`（每轮扣费记录，带时间戳），按时间窗口把 `cost` 累计记为花费；结算后推进终点（`out/team/billing_cycle.json`），绝不重复计数。规则：
- **巡检会话：开窗/收口实结**——第 1 步 `billing.py --task-begin --ledger 50k --note 每日巡检`，收口第 5 步 `billing.py --task-end --ledger 50k --note 每日巡检`；口径 = 「开窗 → 收口」对话时间窗内 `events[]` 的 `cost` 求和（`basis=events-window`；两次累计快照差额做对账），`source=task-window`、`estimated=False`，即这次巡检真实花了多少；结算后周期终点一并推进，不会重复计。
- **周决策会话：两笔实结**——第 2 步 `billing.py --cycle-end --ledger 50k` 补记「上次结算终点 → 现在」（若撞上未收口的巡检窗口，先结算窗口再补窗口前空档）（覆盖上次决策会话之后到现在的消耗，多为期间巡检与会话外消耗）；第 10 步再 `billing.py --task-end --ledger 50k --note 决策 <本数据日>` 补记当次决策会话（上次终点 → 现在）。两笔按终点递进，绝不重复。
- **月报不记账**：月报会话不跑结算，消耗由**下一次周决策第 2 步**补记时一并计入。
- **周报单列「上周技能花费（实扣）」**：`weekly.py` 的 `week_skill_cost(ledger, as_of, days=7)` 从 `out/budget.json` 的 runs 里取 `recorded_at` 落在 [as_of−6, as_of] 的 cost 合计与次数；这是展示事实，不参与评分/阈值。
- **区间内所有本机消耗都计入**（含开发对话等非决策会话）：`events[]` 没有 session id，按时间切分是唯一可复现口径。
- 账户余额观测（`accounting.books[active].days[*].debitUnits`，1e8=1 元）只作参考字段 `account_delta_cny` 与日结披露，不参与任务记账。
- 缺失/异常：读不到 `events[]`、窗口无记录或结算失败 → 不记账并如实报错（巡检失败就报原因、不手填）；绝不编数字、不按单价公式估算。

四个诊断指标（超额 vs 沪深300 / 最大回撤 / 胜率×盈亏比 / 费用占比）照常报，只作**诊断信息**——解释「为什么赚/亏」，不单独否决策略。
最小观察窗 12 周、成交 ≥10 笔才判期望；不足就如实说「样本不足，还不能判断」。
**不许**把模拟盘结果说成「验证成功，可以上真钱」；也不许承诺任何收益率。

**必须把「权益层」和「现金层」拆开报**：净值里已含 `cash_yield`（朝朝宝/货基 + 逆回购，利率取 `config.cash_rates()`，净口径见下），所以「总收益 +3.8%」里可能有一大块来自 R1 现金层。回答「能不能挣钱」要给三个数：①权益层盈亏（持仓涨幅 − 卖出实现亏损，剔掉利息）②现金层利息（R1）③总收益。**只报总收益等于把现金利息冒充策略收益。** 现金层不是「空仓」：R2/R3 没机会时它就是 R1 配置（§8.3「不留闲钱」），但也不能拿它证明选股有效。

**现金层达不到验收线（三条硬结论）**：
① **现金层加权用净口径**：半流动性货基池用各支 **90 天实得年化加权**（货基无申赎费，净值已扣运作费）；朝朝宝/R1 用其 7 日年化、无交易费。**逆回购不属于现金层**（§5.7c），若算回现金层必须扣年化佣金（7/14/28 天期 0.005%/0.010%/0.020%、每年 52/26/13 笔 ⇒ 年费 **0.26%/本金·年**；券商折扣用 `repo_commission_discount` 折算）。**不许拿毛利率当净收益**。分工固定：挂单资金留朝朝宝（T+0），观望资金进半流动性货基池（90 天口径前 3 支、每支 ≤1 万快赎）；利率现算（`cash_rates()` + 排行文件），不写死。
② **满仓现金跑不过无风险存款**：结构性的（现金层净利率低于定存线），结论写死、金额现算。若把一部分现金换成 R1 现金管理类理财，必须用登记的真实 7 日年化计息并标注口径，不许引用无公开净值的产品。
③ 所以达标路径只能是「R2 场外腿 + R3 权益层正收益」；5 万本金的正确预期是「不亏 + 流动性 + 不留闲钱」，本金更大才谈得上「扣 token 后跑赢定存」。
§8.7 的计息版回放按毛利率上限算，读作「上限」，不是预期收益。

### 8.5 迭代怎么改

每周复盘只允许改两处：①**执行层参数**（`config.PAPER` 的最小交易额、不交易带、现金缓冲）；②**观察点清单**。改选股/打分/否决线的阈值必须走 `references/thresholds.md` §4 的阈值纪律，且**不许**因为某只没买到、亏了钱就回头改规则（拟合噪声）。

**改完代码先证明可复现**：任何影响结论的改动（筛选/打分/仓位/撮合）后必须跑 `determinism.py --capital 50000 --tier B`——同一份缓存跑两遍，`out/` 下**全部 CSV/JSON** 归一后必须一致（JSON 先剔除时间戳类易变键再按 key 排序；provenance 只比 `(kind,key)` 集合，日期可不同）。两遍不一致说明有隐藏不确定性（线程落盘顺序、字典遍历、浮点累计），此时**不许**上线，否则「同一份数据必得同一结论」和复盘归因都成假的。

**调仓模式也算规则**：账本默认 `regime_change`（回放依据见 engine-notes §七）；`full` 模式（每周按目标全额重建）回放年化转负，不采用。改任何账本的模式必须走一次 git 提交写明理由。
**个股组合构造也算规则**：`EXEC.stock_weighting`（rank / conviction）、`max_stock_names_by_ratio`、`rank_weights` 与数据新鲜度口径（交易日 19:00 本机统一取数 / 报告「数据截至」）都属会影响结论的规则，改动必须走一次 git 提交——不许盘中临时改，也不许因为某只没买到、亏了钱就调排名权重（拟合噪声）。

### 8.6 边界（每周都要在周报里重复）

模拟盘不是真钱：不产生真实委托、不接券商、不构成投资建议；触发价不是保证成交价；本部署本金 **5 万**，只做 A 股 + 场内 ETF。单账本模拟「5 万小资金真实形态」（ETF 承接 + R2 场外腿 + 现金层）；**不要把 5 万账本的成绩当成整套策略的成绩**——选股层有没有用，要看 12 周前向数据与 engine-notes §七 的回放证据一起判断。

### 8.7 回放证据（要数字/结论先看这里，完整表在 `references/engine-notes.md` §七）

`scripts/backtest.py` 用真实历史日线回放 ETF 承接层（个股层无 point-in-time 数据，不能回放）；现金层按 `config.cash_rates()` 实测口径计息（见 §8.4）。

**三条必须一起说（否则数字会被误读）**：
1. **账面正收益来自「大比例现金吃利息 + 低换手」**，权益层本身不是 alpha 来源，不是择时/选股。
2. **交易频率是第一成本项**：最低佣金 5 元/笔，换手把收益吃光 → 账本用 `regime_change`。
3. **利率假设决定结论**：现金层净利率按当日实测；低于定存线则扣 token 后必然达不到对应年化额 → 达标只能靠 R2/R3 层。金额现算。

**再投资口径**（`--reinvest`）：可投资本 = 本金 + **已实现盈利**（卖出落袋盈亏 + 现金层净利息，上限 `config.CAPITAL["max"]`），期末仍是本金口径（亏损不缩本金），真赚到才抬高仓位。产物 `out/backtest_compare.md`。

#### 8.7.1 PIT 全集回放（去掉「用今天筛出的 ETF 回放过去」的生存者偏差）

`scripts/etf_pit.py` 从新浪 ETF 全表逐日 as-of 判合格、清盘按最后成交价清算，得 PIT 池。完整收益/回撤/显著性见 `references/engine-notes.md` §七。

读法（结论不随数字变）：策略层「跑赢零」把握较高，但「跑赢沪深300」仍与运气分不开；权益层区间刚碰 0，**不能宣称已证明 alpha**；且这是同一样本里挑出的最好变体（选择偏差），须前向验证。**按用户验收口径（token 回本 + 跑赢存款）账本用 `regime_change`**；基准线见 §8.4。`once`/`incremental` 保留为开关（见 §8.5）。

### 8.8 利润再投资（可投资本）

- **可投资本 = 账本本金 + 累计已实现盈利**（只算落袋两块：卖出流水 `realized_pnl` 之和、现金层净利息 `Σ(interest − fee)`；都已扣费）。浮盈不算：按浮盈放大仓位等于追涨加杠杆，回撤反噬。亏钱**不缩本金**。
- 上限由 `config.CAPITAL["max"]` 兜底：超出部分留现金层（朝朝宝/货基池；逆回购按 §5.7c），不越界扩大。
- 决策日管线按可投资本跑：`run.py --capital <可投资本>`，`weekly.py` 自动算并把「可投资本」写进周报头部（与本金不同才显示）。
- 什么时候真投出去：**重建仓事件**（首次建仓、市场状态变化、挂单全灭、止损/熔断清仓后再建），**外加复利兜底**——状态没变但可投资本比上次建仓时变动 ≥1%（`paper.rebuild_due()` 的 `last_rebuild_capital`）也重建一次；**再加闲置现金兜底**：状态未变但权益市值低于该状态权益上限时，允许**只买不卖**补建仓到上限（`paper.cap_topup_orders()`，累计买入 ≤ 剩余空间 98%）。
- 不到 1% 的钱不折腾（最低佣金 5 元/笔，几百元反复交易不划算），这段时间在 R1 现金层计息（朝朝宝/货基池；逆回购按 §5.7c，不留闲钱）——换手纪律，不是 bug。
- 实现见 `paper.investable_capital()` / `paper.cash_interest_total()` / `paper.rebuild_due()`，断言见 `_selftest_paper.py`。

### 8.8.1 收益怎么算（用每日巡检的日度净值，不是只比两个决策日）
- 巡检（交易日 20:00 DSH 会话，纯代码 0 token）每天往账本 `nav` 追加当日净值；决策日再结算一条（同日覆盖）→ `nav` 即日度净值曲线。
- 周报「账本表现」（md 与 HTML 都有）直接读这条曲线：区间收益 `末/初 − 1`、日度收益序列、年化波动（×√244）、最大回撤（逐点峰值法）、正收益天数/胜率、与沪深300（`bench_nav`）的超额。区间起点 = 上期决策日 `as_of`，终点 = 本期 `as_of`。
- 实现在 `navstats.py`（`stats()` / `render_md()` / `render_html()`，全库唯一实现）；手工看：`navstats.py --ledger 50k [--start D --end D]`。断言见 `_selftest_navstats.py`。
- 口径纪律：`nav` 为空就照实写「本期没有日度净值记录」，**不许把「没有数据」写成「收益 0%」**。

### 8.9 账本回滚（真出事时 30 秒内退回上一次好状态）

```powershell
$py rollback.py --ledger 50k --list      # 列出备份（含每份的现金/净值/挂单/成交摘要）
$py rollback.py --ledger 50k --dry-run   # 预览「恢复到最近一份」会变成什么
$py rollback.py --ledger 50k             # 真正恢复到最近一份
$py rollback.py --ledger 50k --index 2   # 恢复到倒数第 3 份（-1=最近）
```

- 备份由 `weekly.py` / `paper_exec.py` **改账本之前**自动生成：`<账本目录>/_backup/<账本名>.<微秒时间戳>.json`；保留两条闸门：**份数上限** `config.PAPER["backup_keep"]`（默认 30）+ **保留天数** `config.PAPER["backup_keep_days"]`（默认 7 天）；**周决策（`weekly.py`）生成新备份后顺手删掉 8 天前及更早的备份**（删上一周的账本即 14-8 天前，更早的一并删）；最新一份永不删——哪怕很久没决策、唯一那份已过期也留着，保证回滚能力不归零。
- 回滚**本身可逆**：恢复前把当前账本再备份一次，「回滚错了」还能滚回来。
- 恢复前校验备份结构（缺 `meta/cash/holdings/trades/orders/nav` 直接拒绝），不拿坏文件覆盖好账本。
- 回滚后先跑 `doctor.py --ledger all` 确认 GO 再决策。

### 8.10 决策新鲜度（漏跑一期不会报错，只会静默拖期）

`doctor.py` 读 `out/paper/decision*_latest.json` 的 `as_of`，问「上次决策是哪天」：超过 **8 个自然日**没更新 → WARN（周三/周六决策日应各有一次；阈值 8 天为覆盖长假保守取值）；快照日期在未来 → WARN（时钟/数据异常）。只提醒、不拦决策——可能只是机器关了一周，补跑一次就追上。

### 8.11 逆回购盈亏分析框架（投资层脉冲择时）

> 完整框架（两层口径、KPI、周报/月报落点）见 `references/repo-analysis.md`。

核心：逆回购是**等报价的投资层工具**，不是现金层常驻仓位——平时钱在货基池（§5.7b），只有 GC 利率显著高于货基时才做脉冲。
### 8.12 个股组合构造：排名篮子

**conviction 口径**（`EXEC.stock_weighting="conviction"`）：买入区=核心仓 1.0、观察区前 2–3=试探仓 0.5（需把 `EXEC.watch_weight` 设回 0.5，否则观察区仍按 0 权重）。买入线是绝对门槛（`references/thresholds.md` §4），多数周只有 0–1 只达标，该只独占个股层 50%+，连续多期同一只 → 看起来像只认一个股票。
**默认口径**（`stock_weighting="rank"`）：买入区 + 观察区按总分合并排序，取前 N 只（随档位 3/4/5），系数 `EXEC.rank_weights=[1.0, 0.85, 0.70, 0.55]`，观察区再乘 `EXEC.watch_weight=0.0`（只占名额、不建仓）；单票仍 ≤10%、行业仍 ≤25%、总敞口仍受市场状态上限约束。买入线/观察线不变，买入区仍是「高确信」标签，资金按排名分配、不只给买入区。
**验证**：同一份缓存只换 pick 规则的对照——rank 下个股层更分散、第一名集中度下降（明细见 `references/engine-notes.md` §七）；「0 只买入区」的周照常给排名篮（按档位 3/4/5 只）。
**开关**：`config.EXEC["stock_weighting"]="conviction"` 即切换，无需改代码；改口径须走一次 git 提交。
**边界**：分散化只降低单票依赖，不能证明 alpha；个股层仍不能回测（缺 point-in-time 数据），要看 12 周前向数据。
