## 一、数据流：一次完整运行经过哪些环节

```
              ┌─ 新浪 / 中证 ─────────────┐
  取数层  ────┼─ 百度估值 ────────────────┼──→ 缓存 cache/（同一交易日复用，跨日换命名空间）
              ├─ 东方财富 fund_*（场外基金）┤
              ├─ 同花顺 fuyao（可选第二源）─┤
              ├─ 巨潮 cninfo（公告）───────┤
              └─ baostock（PIT/指数成分）──┘
                            │
   清洗层  datasource.py ───┤ 类型归一 / 代码补零 / 份额折算剔除 / 前复权对齐 / provenance 落盘
                            │
   漏斗层  screen.py ───────┤ L0 沪深300 → L1 规模·流动性·上市满 750 交易日 → L2 ROE·现金流·负债率
                            │ → L3 成长·估值分位 → L4 粗排 top_n      输出 out/stage1_all.csv（每层淘汰数）
                            │
   补充池  etf.py ──────────┤ 场内 ETF 池（R3 承接；流动性 + 四道门槛 + 同指数去重）
           wealth.py ───────┤ 场内债券 ETF 池（R2）
           otc.py ──────────┤ 场外债券基金池（R2，小资金买不起场内一手时的承接；与场内池互斥）
                            │
   判断层  judge.py ────────┤ 四道否决（一票否决）→ 四维打分（各 25 分）→ 价位 → 可证伪条件
                            │ 输出 out/stage2_judged.csv / stage2_detail.json
                            │
   组合层  plan.py ─────────┤ 市场状态 → 档位 → 仓位上限 → 排名篮子 → 整手化 → ETF 承接
                            │ → R2 场外承接 → 现金层拆单 → 费用测算 → 风控闸门 → 三批建仓
                            │ 输出 out/stage3_plan.md / .json / stage3_orders.csv
                            │
   记账层  paper*.py ───────┤ 模拟账本按「卖出次一交易日开盘价 / 买入限价条件单」成交；weekly/monthly 出记分卡
   编排层  team.py ─────────┘ T0–T10：LLM 只做判断，重复执行全在代码里
```

**一句话原则**：**凡要重复执行的写进代码，凡只判断一次的交给 LLM**。
LLM 的价值不是「算得更准」，而是「动机分离 + 把模糊判断说成可证伪的话」。

## 二、计算逻辑（每个数字的公式）

> 三阶段判据的完整执行细节唯一出处是 `SKILL.md` §1，本节只做映射：给公式、给代码位置、给键名，**不重写执行细节、不复制阈值数值**。

| 环节 | 代码 | 公式 / 口径（数值见 `config.py` 对应键） | 细节出处 |
|---|---|---|---|
| 市场状态与仓位上限 | `plan.py`、`capital.py` / `config.CAPITAL` | `deviation = (沪深300 收盘 − MA200) / MA200`；`目标仓位 = min(档位目标, 市场状态上限)` | `SKILL.md` §1 阶段三 |
| 个股筛选（L0–L4） | `screen.py` / `config.L1`…`L4` | 逐层判据见 SKILL；L4 = 按粗排分取前 `top_n` 只 | `SKILL.md` §1 阶段一 |
| 个股打分与否决 | `judge.py` / `config.VERDICT` | 四维各 25 分 → `总分 = 质量 + 成长 + 估值 + 风险`；四道否决一票否决 | `SKILL.md` §1 阶段二 |
| 价位（买入/目标/止损/移动） | `judge.py`、`capital.py` | 全部由 PE 反推（见下「价位」） | `SKILL.md` §1 阶段二 |
| 组合构建 | `plan.py`、`capital.py` / `config.CAPITAL` | 排名篮子 → 单票/行业上限校验 → 整手化 → ETF/场外承接 | `SKILL.md` §1 阶段三、§8.12 |

**分位口径（最容易搞混的一条）**：`pe_pct_ind` = 当日**同行业横截面**分位（不是自身历史分位）；
自身历史分位（近五年）只在价位与目标价里用。**两把尺子不要混用。**

### 价位（全部由 PE 反推，不用 DCF）
```
EPS        = 现价 ÷ PE
买入价     = EPS × 自身历史 PE 分位 25% 位数值 × 0.7  （再保守 30%）
目标价     = EPS × min(自身 5 年 PE 中位, 行业 PE 中位) （且不低于自身分位 25% 位）
止损价     = 买入价 × 0.85                  （只是**计划占位价**：下单/括号单参考；
                                              成交后硬止损 = 实际成交成本 × 0.85，由 paper.apply_fill 写入）
移动止损   = 现价 − 2.5 × ATR14                      （浮盈 > 10% 后启用）
```

### 组合构建（公式）
```
ranking   = 按总分排序取前 N 只（N 与权重系数见 config）
权重      = 系数 × 单票预算（系数非占比、不归一）
lots      = floor(预算 ÷ (价 × 100))，允许 12% 取整容差（见 config）
一手超单票预算 → 该股标 unaffordable，预算转 ETF 层；ETF 也买不起 → 转现金层
单票/行业上限在权重与整手后金额两处双重校验
```

### 费用（小资金的真摩擦）
```
单笔佣金  = max(成交额 × 佣金率, 最低佣金)          ← 费率与最低值见 config.ACCOUNT
过户费 / 印花税 = 见 config.ACCOUNT（仅股票，方向不同）
单边成本率 = 费用 ÷ 成交额；往返 = 2 倍
```
**关键事实**：最低收费 ÷ 费率 = 追平点金额，5 万本金的单笔永远够不到
→ **成本率恒等于「最低收费 ÷ 单笔金额」，费率数值不改变结论，笔数才决定成本**（推导见 `SKILL.md` §1）。

### 现金层
```
逆回购：手数 = floor(可用现金 ÷ 每手金额)（每手金额见 config）
        净收益 = 毛收益 − 日滚佣金（佣金口径见 SKILL §8.11）
零头：   不足一手的钱放场外货基（T+1）
现金层净年化 = `config.cash_rates()` 现算 —— **不写死数字**
```

### 记账与评分
```
成交价：卖出（减仓/清仓/止损）= 下一交易日开盘价；买入 = 限价条件单
        （开盘 ≤ 限价按开盘价，否则盘中最低价触及限价按限价；未触价 `limit_expire_days` 后失效）
        （下单窗口 15:00–15:30 → 订单进次日集合竞价/盘中挂单）
净收益率 = (期末净值 − 期初净值) / 期初净值 − token 成本率
token 成本率 = 年内 token 花费 ÷ 本金（按本金折算，见 config.token_cost_annual）
评级门槛与奖励档位 → 见 config.SCORE（口径见 SKILL.md §8.8.1）
奖励 = 净利润 × 评级档位%，一半转入下一年预算（不要全转，否则预算膨胀→门槛自抬）
```

### 网格（低买高卖，当前关闭）
```
目标权重 = base_weight − (偏离度 ÷ step_pct) × 每格调整
触发区间 = ±band_pct；单笔 ≥ min_order_cny；间距 ≥ spacing_pct；年换手 ≤ max_round_trips
状态：enabled=False —— 回测否决证据见 `team-framework.md` §6
```

## 三、可靠性护栏（为什么这些数字可追溯）

| 护栏 | 做法 | 触发后果 |
|---|---|---|
| 单一出处 | 阈值只在 `config.py`；费率只在 `config.ACCOUNT`；利率只在 `config.cash_rates()` | 改一处全局生效，不会两套口径打架 |
| 数据血统 | 每次取数写 `provenance_*.json`（接口 / 时间 / 行数） | 汇报里能说出「这个数是哪天从哪个接口来的」 |
| 完整度 | 单票关键字段完整度 < 80% | 标「数据不足」，不参与排名（不猜） |
| 四道闸门 | 准入 / 预算 / 组合 / 评审，任一不过就 fail-closed | 宁可空仓，不降标准 |
| 可复现 | `determinism.py` 连跑两遍，结论文件逐字一致 | 不一致就是 bug，先修再谈策略 |
| 缓存隔离 | 缓存按交易日命名空间 | 防止昨天数据混进今天 |
| 降级 | 第二源（同花顺/巨潮/baostock）全部可选 | 挂了退回主源，不阻断主流程 |

## 四、效率要点（为什么跑得动）

- **缓存**：同一交易日内所有接口复用，跨日自动重取；一次全量场外池扫描约 100 秒。
- **批量优先**：能传代码数组的接口绝不逐只请求（快照接口支持 100 只/次）。
- **先预筛后取历史**：新浪全表按当日成交额 ≥1 亿预筛，省掉上千次历史请求。
- **并发取价**：个股打分阶段按线程池并发，失败逐只降级而不是整批失败。
- **LLM 只在五个点位出场**（研究 / 深取标签 / 命令单 / 评审 / 复盘；先后顺序唯一权威见 `SKILL.md` §8.1.1），且只传文件路径不传大段数据。
- **token 预算**：按本金折算（见 `config.token_cost_annual`）；「省 50 元 token ≈ 权益层多赚 0.58%」这个量级见 `references/team-framework.md` §0。

## 五、改代码前的检查清单

1. 改阈值 → 只改 `config.py`，然后跑 `determinism.py` 看产出是否仍两遍一致。
2. 改费率/本金 → 改 `config.ACCOUNT` / `config.CAPITAL`，连带检查三批建仓、ETF 承接、网格下限三处结论。
3. 改数据接口 → 更新 `data-sources.md` 的可靠性等级，并确认 `provenance` 仍能落盘。
4. 新增 LLM 步骤 → 先问「这一步是不是重复执行」，是就写代码；并登记进 `team.py` 的 `STEPS`。
5. 任何结论要进汇报 → 必须能回答「这个数从哪个接口、哪天取的、用什么公式算的」。
