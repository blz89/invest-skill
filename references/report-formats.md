# §6 汇报格式（`SKILL.md` §6）

> 周报/HTML/月报的版式与顺序以本文件为准，`SKILL.md` §6 只留指针。

1. **一句话结论**：市场状态 + 买入区/观察/回避几只 + **个股买得起几只、ETF 承接多少**。
2. **漏斗**：多少只 → 多少只，卡在哪层最狠（说明分项不可相加）；ETF 漏斗同理单列一行。
3. **订单清单表**：代码/名称/得分/权重/现价/买入价/止损价（**占位价**，成交后按实际成本×0.85 重设）/目标价（ETF 行标「ETF」+ 1 手成本与手数）。先用**全候选排名表**回答「为什么是这几只」：总分、距买入线差多少分、谁进了组合；连续几期排第一多为**评分粘性**（基本面/估值分位变化慢），并给出报告头部的**数据日期**。
4. **买不起的怎么办**：列「1 手超单票预算」的标的与所需本金，说明权益预算改由哪些 ETF 承接。R2 层一手买不起时说明是否改由场外短债承接（看 `out/stage1_otc.csv`）；**场内与场外只报一条腿，不许两头都报成「买到了」**。
5. **至少一只的具体判断卡**：支柱、风险、证伪条件。
6. **本期触发的风控**：为什么仓位只有 X%；档位是否被市场状态压回。
7. **现金层**：挂单资金多少留朝朝宝、观望资金按 90 天口径摊给哪几支货基（金额/利率/数据日）、预期年化——**引用半流动性排行文件的 90 天实得年化并报「元」**（口径与三条硬结论见 §8.4，不许写未扣费的毛数；排行过期标 ⚠）。**金额现算**：本金 × 加权净利率 = 年化元数，再并列「扣 token 后」与「同等本金按定存线」两个数（定存线见 §8.4）。结论方向固定，数字每次现算，不许沿用写死的金额。逆回购若当期脉冲择时判 GO（`repo_pulse.py`），单列一节写报价/占款天数/超额，不混进现金层年化；同时写「不承担权益风险的部分，不是承诺收益」。
8. **费用**：一次性买入费用、来回费用、有没有「佣金 >0.5% 的高佣金订单」。
9. **边界一句**：边界全文见 §8.6。

数字必须来自当期 `out/` 产出，不许沿用上一期结果冒充当期（跑失败了就报失败）。

**周报顺序（收益/消耗置顶、策略后置、附录不重复）**：0) 先给 HTML 报告路径（`out/paper/report_{日期}.html`；不存在就说明原因）；1) **收益与消耗（核心，一张表）**——净值/本金、账户收益、同期沪深300/超额、最大回撤/仓位、现金+利息、净利润/净收益率（**不写档位/奖励**：决策日不评分，档位与奖励只在年报出、每年 1 月 1 日定档；口径见 `references/paper-ops.md` §8.4），另单列一行「上周技能花费（实扣）」（budget runs 按记账日 7 天合计，`weekly.py` 的 `week_skill_cost`，只展示、不参与规则）；2) 本期操作（成交/订单与挂单/为什么动·不动）；3) 策略与持仓（市场与目标组合、风险等级）；4) 下期观察点（止损价 + 前两条证伪条件）；5) 边界一句。**附录（按需看、不进正文）**：账本日度表现、账户账本明细、与上期变化、本周巡检汇总、**收益拆解（权益 / 场外 R2 / 现金三层，`breakdown.py` 生成，不许只报总收益）**、场外债券基金影子账；报告里**同一数字只出现一次**。
**HTML 版式固定为三卡简报（B 版）**：① 这周赚了没（账户收益 / token 实花 / 净利润 / 超额）+ 一行回撤/仓位/现金；② 现在拿着什么（持仓表：名称/股数/成本/现价/盈亏/止损 + 一层资金）；③ 下期什么条件动手（下一决策日 + 各持仓止损触发表）；其余章节（计划与订单 / 收益拆解 / 筛选打分 / 账本表现 / 风控 / 场外）全部收进 `<details>` 折叠区，默认不展开。**`weekly_<日期>.md` 结构不变**；版式只在 `scripts/report_html.py` 改，数字口径不动。
**月报 HTML 固定为周报式简版**（`report_html.build_monthly_report`）：首屏一句话 + 四节（①这个月赚了没 / ②这个月做了什么 / ③记分卡（月报不判档）/ ④下月什么条件动手），复盘/技能优化/诊断/五问/本年计划/记分卡全文/指标表/收益拆解/按标的/拆账全部收进 `<details>` 折叠区；`monthly_<月>.md` 结构不变。
**月报顺序**：0) 先给 HTML + md 路径；1) 一句话（账本净值/月内收益/沪深300/超额）；2) **上月策略复盘（必写，不是统计）**：逐条回查假设（regime 判定是否滞后、权益预算用满没、ETF/场外承接是否落地、三批建仓条件单成交/失效、止损事后对错、现金层是否跑赢、费用与换手），每条带证据，给 ≤5 条改进项并分 A/B 类；3) **技能优化（A 类当场执行）**：T10 列技能自身优化点，A 类（bug/文档/报告可见性/性能/兜底/测试缺口）由 Lead 当场改代码/文档 → `selftest_all.py --fast` → git 提交 → 回填 `retro.md` 的 `- [x]（commit <hash>）`；B 类（阈值/规则/预算/仓位/交易参数）写 `out/team/pending_changes.md` 等用户拍板；4) 关键数字（收益/回撤/成交/费用/现金层利息/权益层；含**收益拆解**——固定「四、收益拆解」表，`breakdown.py` 全库唯一实现、md/HTML 同源）；5) 逐笔成交与按标的归因（含场外影子账）；6) 止损/熔断次数与事后对错；7) 对标差异（账本 vs 沪深300）；8) 记分卡：月报**不判档**，只引四项口径与季进度；档位/奖励在年报定档（本年各月等价年化算术平均）；9) 下月计划（按「一、策略复盘」改进项执行，改规则先登记 engine-notes）。`monthly.py` 自动把 `out/team/retro.md` 的「策略复盘」「技能优化」摘进月报 md/HTML（缺节显示 ⚠，不伪造），并附「自动诊断信号」（结算点/挂单/仓位/费用/场外腿/现金层，代码只报事实）。
