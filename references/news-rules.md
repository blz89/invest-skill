# 事件面采集与判读手册

> 谁读：**采集端（脚本）**（采集、整理简报）、**Lead**（判读高优先级事件、出 `mult`、定持仓处置）、改代码的人（阈值口径）。
> 单一出处：角色分工=`references/team-framework.md`；决策日顺序=`SKILL.md` §8.1.1；事件面规则与校准证据=本文件。
> 口径代码：`scripts/news.py`（`R_EVENT` / `C_EVENT` / `r_score()` / `c_score()` / `tier_of()`）。
> 校准数据：`out/news_calib.csv`（两池 602 条事件）。校准脚本：`scripts/news_calib.py`。
> 标定数据日：2026-10-29。**标 [先验] 的权重没跑过数据，不许说成「实测」。**

---

## 一、谁来做，各自负责什么

**事件面 = 采集端（脚本）采集、Lead 判读**：把持仓与候选的公告/新闻/异动译成「R 分风险 + C 分催化」，交出 `mult`。

**采集端（纯代码，0 判断）**：整理 19:00 已取产物（`out/stage3_plan.json` 的 `data_as_of`、`stage1_funnel.json` 取数成功率、候选/持仓清单；不是最近交易日就如实报告，**决策日不重取行情**）→ 扫持仓+候选事件面（公告、新闻、异动、除权）→ `news.py` 按规则打 `r_score`/`c_score`、定处置档 → 交卷 `out/news_events.csv` + `out/news_brief.md`。

**Lead 判读端（决策日一次性判断）**：逐条确认高优先级事件（什么事、影响谁、按哪档、为什么）→ 按档给 `mult`（权重系数；**持仓处置手工出单**，代码不会自动减半）→ 高优先级事件逐条写人话，结论放 `news_brief.md` 顶部。

**都不做**：不改资格（归漏斗与四道闸门，事件面只否决/加减权重）；不预判点位（目标价、涨跌幅）；不碰 ETF/场外基金/现金层（无个股事件面，只扫**个股**）；不做每日巡检（`patrol.py` 管账本/数据/任务书一致性）；不自己加数据源（只用 `news.py` 封装的同花顺 iNews + 巨潮公告）。

## 二、什么时候跑

| 谁 | 什么时候跑 | 干什么 |
|---|---|---|
| `stock prefetch` + `run.py`（交易日 19:00，Windows 任务）与 `patrol.py`（交易日 20:00，DSH 会话） | 周一至周五 19:00 / 20:00 | 19:00 `python -m stock prefetch` 取收盘基础数据 → `run.py --capital 50000` 只读热缓存出 stage1/2/3；20:00 `patrol.py` 查账本/任务书一致性。**不看新闻。** |
| **事件面**：脚本采集 + Lead 判读 | **只在决策日**（周三/周六 20:30 那轮，研究层交卷前；**不重取行情**，只采决策日新增公告/新闻：周三采周一至周三、周六采周末） | 扫持仓+候选事件面，出 R/C 与处置档 |
| Lead | 决策日当晚 + 次日早间 | 按档改权重、安排调仓（引擎只算手数与价位；下单/成交走 `paper.py` 或手动） |

**为什么不是每天**：新闻衰减极快（≤3 天 15 分、≤30 天 8 分），每日扫却不用等于换噪音；**周六决策无新行情，周末新增公告/新闻是别处拿不到的新信息；周三决策则采周一至周三的新增信息**——事件面留在决策日、行情不重取；要命的事件次日上午由 Lead 处理。

决策日位置（完整 10 步唯一权威见 `SKILL.md` §8.1.1）：

```
体检 → 漏斗(规则) → 引擎出候选 → 【事件面：脚本扫候选+持仓 → Lead 出 mult】→ 研究层 → 计划书 → 次日执行（卖出开盘价 / 买入限价条件单）
```

**为什么在这里**：设计是「专门收集**研究层筛选出的**优质项目的新闻」，只扫候选 + 持仓，不做全市场海选。`mult` 由 `plan.apply_news()` 定稿时乘进权重，**必须定稿前交卷**；交晚这轮退回「不看新闻」，但要如实说明。

## 三、具体怎么干（六步）

### 第 1 步（采集端（脚本））：确认输入齐了
```bash
& $py news.py --help
ls out/stage3_plan.json out/stage1_candidates.csv     # 持仓与候选
```
持仓取 `positions` 中 `layer == "个股"`；候选取 `out/stage1_candidates.csv` 前 `config.NEWS["max_codes"]` 只；都空 → 空简报，**不编事件**。

### 第 2 步（采集端（脚本））：跑扫描（纯代码，0 判断）
```bash
& $py news.py                # 默认窗口 config.NEWS["days"]
& $py news.py --days 7       # 只扫最近 7 天（周末补扫用）
& $py news.py --limit 5      # 只扫 5 只（调试用）
& $py news.py --offline      # 断网时出空简报，不报错
```
抓取 → 噪音过滤 → 硬雷关键词 → 打 R/C → 定档 → 写 csv 都在本步；**分由规则算**，人的判断在第 3–5 步。

### 第 3 步（Lead）：读结果，先看高危
```bash
# 读 out/news_brief.md（按 level 排序，高优先级在最前）
```
顺序固定：**先「高」→ 再「中」→ 最后扫低优先级有无漏网硬雷**。

### 第 4 步（Lead）：对每条高优先级事件写一句人话
三件事：**是什么**（公司、事件、发生日、来源）；**影响谁**（持仓/候选，占组合多少）；**哪一档**（否决 / 降权40 / 降权15 / 加分15 / 加分10 / 不干预）+ 为什么。

### 第 5 步（Lead）：结论（写进 `news_brief.md` 顶部）
只写三行：
```
- 否决：000977（立案调查，R=60）→ 持仓处置由 Lead 在决策日手工出单（代码不会自动减半）
- 降权：600519（诉讼仲裁，R=45 → 0.60）
- 加分：000999（回购，C=16 → 1.10）
```
没有就写「今日无需要干预的事件」。**不要罗列全部事件**，那是 csv 的活。

### 第 6 步：交卷 + 自检（改过权重才需要）
```bash
& $py _selftest_news.py       # 必须全过
```
汇报带三样：扫了多少只、事件多少条、需要干预几条。

## 四、输入 / 输出契约

### 输入
```
out/stage3_plan.json → positions：持仓股名单（缺 → 只扫候选）
out/stage1_candidates.csv：候选股名单（缺 → 只扫持仓）
`fuyao.py`（同花顺 iNews）：新闻/公告/异动/除权（挂 → 退巨潮；仍挂 → 空简报 + 报警）
`cninfo.py`（巨潮）：公告正文与日期（同上）
```

### 输出
`out/news_events.csv`（一条事件一行，列固定）：
```
layer, code, name, kind, level, tag, date, title, source, url,
r_score, c_score, net_score, tier, mult
```
- `tier`：处置档名（否决 / 降权40 / 降权15 / 加分15 / 加分10 / 不干预）
- `mult`：权重系数（0.00 / 0.60 / 0.85 / 1.15 / 1.10 / 1.00）——**下游只认这一列**
- `url` 与 `date` 缺失的事件**直接丢弃**（不可追溯的新闻等于没有）

`out/news_brief.md`：人读简报，按 level 排序，顶部是第 5 步那三行。

**下游怎么用我**：`plan.py` 的 `apply_news()` 读 csv，按 `code` 取最强 `mult` 乘进权重，再写 `research_filter`。`mult` 错 = 权重错 = 决策错。

## 五、两套分，方向相反

### R 分（风险，0–100，越高越危险）
```
R = 事件基线(0–60) + 0.5 ×（来源确定性 0–15 + 时效 0–15）
```
**无风险事件时 R 恒为 0**：来源与时效只放大「已发生的风险」，绝不凭空造风险（五维直接相加，普通公告也能拿 30 分被降权）。

### C 分（催化，0–30，越高越值得加码）
```
C = 事件强度(0–22) + 来源(0–4) + 时效(0–4)
   来源项 = 来源确定性 × 4/15；时效项 = 时效 × 4/15
```

### 处置档（R 优先，利好不能冲抵利空）

```
否决：`tag ∈ VETO_TAGS` 或 `R ≥ 60` → 0.00；候选剔除，持仓由 Lead 手工出单（R≥85 建议清仓，须人工确认）
降权40：`R ≥ 40` → 0.60；权重六折，禁加码
降权15：`R ≥ 25` → 0.85；八五折，只记录
加分15：`C ≥ 22` → 1.15；允许在 25% 上限内加码
加分10：`C ≥ 15` → 1.10；允许小幅加码
不干预：其余 → 1.00；只归档
```
`VETO_TAGS = {"立案调查", "退市风险", "会计问题"}` —— 这三个不看总分，直接出局。

## 六、阈值为什么是这些数（成本约束推出来的）

单票上限 = 本金 10%。5 万本金 → 单票 5,000 元，一次往返约 0.4%（推导见 `SKILL.md` §1）。**事件要对单票产生 > 0.4% 影响，动手才不亏。**

校准结果：强正面事件历史超额仅 +1.1% ~ +3.3%，强风险 -10% ~ -23%。所以**否决要狠**（-15% 量级，别扛成本）、**加分要轻**（+2% 量级，只该 1.10–1.15）、中间地带（±5% 以内）一律「不干预」。

## 七、校准证据（两池 12 期，2026-10-29）

方法：12 个窗口（2026-04 ~ 2026-09，每期 10 个交易日取首次出现），事件后 20 个交易日超额收益（相对沪深300），**同窗口内无风险/预警标签的股票作对照**；`差中差(DiD) = 事件组超额 − 对照组超额`。

### 池 A：优质池（候选池 20 只，434 条事件，对照 n=211，对照均值 −2.12%）

```
标签 n：原始超额｜DiD｜误杀(涨超5%)
回购 9：+3.26%｜+4.40%｜0%
分红 9：+3.11%｜+1.68%｜0%
股权激励 3：+1.07%｜+1.76%｜35%
减持 6：−0.83%｜+0.38%｜17%
增持 3：−1.94%｜+0.80%｜33%
重大合同 2：−2.55%｜−1.17%｜0%
质押冻结 3：+0.24%｜+3.55%｜33%
担保 12：+2.68%｜+2.04%｜25%
资产减值 4：+1.71%｜+1.83%｜0%

```
**最大发现：一条硬雷都没有**——池子确实干净，但**硬雷权重无法在本池校准**，须另找样本。

### 池 B：坏股池（近一年被立案/处罚/退市风险/预亏的 ST 股 20 只，168 条事件，对照 n=81，对照均值 −2.73%）

```
减持 2：−21.78%｜−7.53%｜100%｜0%
行政处罚 10：+2.93%｜+11.46%｜20%｜50%
担保 17：−8.68%｜+5.80%｜47%｜18%
资产减值 7：−10.26%｜+7.01%｜57%｜14%
质押冻结 6：−7.41%｜+6.24%｜50%｜17%
```

### 从证据到权重

```
标签 基线分｜依据
立案调查/业绩预亏 60｜−12% ~ −23%，跌超5% 最高
会计问题 55｜−20.8%、跌超5% 100%（DiD 正不可信）
诉讼仲裁 45｜−14.3%，n=6，误杀 0%
退市风险 45｜−10.4%（且在 VETO_TAGS）
减持 20｜−21.8%（坏）/ −0.8%（优）→ 情境依赖
商誉减值/监管措施 30 / 15｜[先验] 按会计风险保守取值
行政处罚 8｜+2.9%、误杀 50% → 几乎无信息量
担保/资产减值/质押冻结 5 / 5 / 6｜两池均无稳定负超额 → 噪音
解禁/再融资 6 / 6｜[先验] 无样本
回购 14｜+3.26%，唯一稳定正超额
分红 12｜+3.11%
业绩快报 10｜+2.80%
股权激励 8｜+1.07%
增持/重大合同/中标 5 / 6 / 5｜−1.94% / n=2 且为负 → 只给一点
业绩预增 10｜[先验] 无样本
```
**为什么以「原始超额」为主、DiD 为辅**：坏股池全线在崩（对照组 −2.73%），DiD 会把「大家一起跌」减掉甚至翻正（会计问题、行政处罚即如此）。判据用 **原始超额 + 跌超5% 比例 + 误杀率** 合看：显著负 + 跌超5% 高 + 误杀 0% → 真硬雷；DiD 正但原始超额负 → 池子beta，仍要扣分。

## 八、出问题怎么办

```
429/超时：`news.py` 自带限速重试 → 连续失败退巨潮公告 → 仍失败则空简报 + 顶部写「事件面未取到」，不许假装扫过
`news_events.csv` 空：先分「真没事件」与「抓取失败」——看 `news_brief.md` 抓取统计行，失败重跑 `--days 7`
url 缺失：该条丢弃（不可追溯），计数「丢弃 N 条无来源」
打分不合理（硬雷只给 20 分）：**不要手改 csv**，改 `R_EVENT`/`C_EVENT` 并跑 `_selftest_news.py`
R 分低却「要命」：最高优先级，记下来，进下一轮重标定触发条件
断网 / 无 key：`--offline` 出空简报，汇报明说「事件面缺席」
```

## 九、已知局限（必须如实说）

1. **硬雷样本来自 ST 股**：5% 涨跌幅限制 + 退市预期，量级可能不同（正常股按 15% 理解偏高）。
2. **样本量小**：业绩预亏 n=2、会计问题 n=2、退市风险 n=3，只算「方向可信、幅度不确定」。
3. **5 个 [先验] 标签完全没校准**（商誉减值、监管措施、解禁、再融资、业绩预增）。
4. **时效衰减是假设**（≤3 天 15 分、≤7 天 12 分…），未单独验证。
5. **内生性死角**：回购、分红本身是管理层信号；信息已部分反映在价格，20 日窗口可能不足。
6. **只测个股 20 日超额**，没测更长持有期与「多事件叠加」。

## 十、什么时候重标定

累计事件 ≥ 1,000 条（现在 602 条），或距上次 ≥ 2 个季度，或出现「明明要命、R 分却很低」的案例（打脸优先），或池子结构变了（如放开创业板/科创板）。

```bash
& $py news_calib.py --n 20            # 优质池
& $py news_calib.py --codes "a,b,c"   # 指定池（坏股池用这个）
```

## 十一、一句话

**R 分决定「还能不能持有」，C 分决定「值不值得多买」。两者都不改变资格，只改变权重；中间地带一律不动手——小资金（5 万本金）不为 ±2% 的事件付 0.4% 的来回。**
