# 决策日提示词（每周六 20:00）

> 用途：**写调度器提示词用的底稿**。调度器里放全文，不放指针；每周可变，但固定部分必须照抄。
> 改法：先改本文件 → 把新全文同步进调度器 prompt（`schedule_edit`）→ 提交本文件。
> 适用：invest 技能、单账本 50k；对应 `SKILL.md` §8.1。规则与阈值以 `SKILL.md` 和 `config.py` 为准，本文件不抄数字。

## 固定部分（每周照抄，不改）

本会话已加载 invest 技能则不再调用 skill 工具。

一、核心任务：**决策 + 修复**（两件，缺一不算完成）

1. **出决策**：按 `SKILL.md` §8.1.1「决策日 10 步」跑完，产出目标组合与行情单；周报 md/HTML 与 T9 计划书都是决策的产物，不是额外任务。
2. **修本周技能问题**：工作日巡检留下的 A 类、本轮执行中新发现的问题，当场修掉（改代码/文档 → `selftest_all.py --fast` 全过 → commit + push → 回填 `[x]（commit <hash>）`）；B 类（阈值/权重/仓位/预算/交易参数）只写 `out/team/pending_changes.md` 等拍板。**第 10 步不做完，决策日不算结束。**

决策日不评分：评分 / 档位 / 奖励只在月报做。

二、开工前（只读，不取数）

- 读 `stock/data/invest/HANDOVER.md`，看当前状态与上次交接。
- 读 `out/team/decision_<上期>.md`，避免上周的结论被遗忘或重复踩坑。
- 读最近一份 `out/paper/lead_decision_*.json`（若有），避免把周五刚减的仓又买回来。
- 读「本月附加任务」（见第八节）。

三、执行顺序（严格按序号，不许调换）

1. `doctor.py --ledger all`（NO-GO 立即停）
2. `billing.py --task-end`（**补记上一周期**：把「上次结算终点 → 现在」的插件扣费记录记进账本并推进终点；本次决策自己的花费留到下次决策第 2 步再记——本会话还没结束、算不准）
3. 只读核对：`python scripts/preflight.py` 必须 READY（数据日期 / 本金 / 取数成功率 / 日摘要四项）；不满足就停，不现场补取
4. 事件面 + 档位：`news.py --days 14`（个股资讯 + 全市场公告流覆盖全池 + 政策面背景）→ `sentiment.py` → `industry.py --refresh` → `macro.py` → `python scripts/regime_probe.py`（落 `out/regime.json` / `regime_brief.md`，牛熊确认直接定档）
5. **研究层（子代理，见第四节）**：`team.py --stage T2` → 起 S1 → `--ingest T2`；`need_deep` 非空 → `team.py --stage T3` → 起 S2 → `--ingest T3` → `team.py --stage T4` → S1 二次（T4 标签）→ `--ingest T4`（落盘后自动跑 T5–T7 规则引擎；评分不在决策日）
6. `run.py --only-plan --capital 50000`（把研究结论乘进权重；不重算研究就白做）
7. `weekly.py --ledger 50k --reuse`（撮合、结算、落 nav、出周报；**决策日必须加 `--reuse`**；顺手做两件只读记录：止损单合并、归档本期选股评分面板到 `out/archive/scoring/`）
8. `review.py --ledger 50k --strict`（账本验收：**样本不足**退出码 0，**未达标**才退出码 1；两种都账本已写完，照常汇报、不重跑）
9. `team.py --stage T9` → Lead 写四段（本期结论 / 策略调整 / 未来 1–3 期规划 / 计费核对（本次不结算）；第 3 段必须含「下周日巡检附加任务」一行，没有写「无」）→ `--ingest T9`（校验四段齐全 + 正文 ≥200 字 + 不能带 `T9_SKELETON` 骨架标记）
10. 收口本周技能问题（见第六节）→ `weekly.py --ledger 50k --refresh-net`（刷新净利润；**本次不结算**）

四、子代理编排

原则：**脚本生产事实，子代理做判断，Lead 拥有写权限并最终负责**。子代理一律 fresh（不继承本周对话），只写约定好的那一个产物文件，不许改 `config`、账本、脚本，不许 push。

| 子代理 | 何时起 | 输入 | 输出（唯一允许写） | 超时 | 校验 |
|---|---|---|---|---|---|
| **S1 研究判读**（T2+T4 合并） | 第 4 步后 | `out/agent_tasks/T2_*.md` 任务书原文 + `out/data_snapshot.csv` + `out/stage1_candidates.csv` + `out/stage2_judged.csv` + `out/news_events.csv`/`out/news_brief.md`（只认池内代码）+ `out/regime.json`（档位背景） | `out/stage1b_research.csv`（T4 时 `out/stage1b_tags.csv`） | 8 分钟 | `team.py --ingest T2/T4`；空理由 / 池外代码 / 缺列即退回 |
| **S2 数据深取** | 仅当 `need_deep` 非空或 T3 提示 | `out/agent_tasks/T3_*.md` + 待深取代码清单 | `out/deep/<code>.json` | 10 分钟 | `--ingest T3`；`per_field_source` 缺字段退回 |
| **S3 独立复核** | Lead 跑 `weekly.py` 时并行 | `out/stage3_plan.json`、`out/paper/weekly_*_orders.csv`、周报 md 数字、账本 | 无（只读，回报问题清单） | 5 分钟 | Lead 必须处理 ERROR 项并在汇报里说明 |
| **S4 技能巡检** | 仅当 `out/patrol_findings.md` 有未修项或本周 `daily_log` 有异常 | `out/patrol_findings.md`、本周 `daily_log`、`summary_*.json` | 无（只读，回报 A/B 清单 + 建议） | 5 分钟 | Lead 决定修哪个；A 类当场修并提交 |

**并行点**：S4 有触发条件，起则与事件面并行；`weekly.py` 跑的同时起 S3。研究链是串行依赖，不许与计划重算并行（顺序错了研究结论进不了当期计划）。

**任务书怎么给**：`team.py --stage T2` 生成的是任务书文件，把**文件全文**贴进子代理 prompt，并明确：①只允许写哪个文件；②必须引用快照字段或任务书事实，不许编数字；③输出字段名照抄契约，缺字段宁可不写也不许猜；④完成后回报「写了什么 + 关键判断的理由 + 引用的文件路径」。

**S1 硬规则**：只对池内标的 `keep`/`reject`/`downgrade`；`reject` 必须写清依据（准入闸 / 行业 / 事件面 / 数据不足）；置信度只是给 Lead 排序用，不许代替理由；研究层只能否决或降权，不许推荐池外标的。事件面「高」级涉及候选必须在 reason 点名（代码+标题关键词）；档位只影响风险证据的严重性判断，**不许因为牛熊改判定标准或加池外票**，`reject` 不许只写「因为熊市」。任务书已带这两段背景（缺失时写「未采集」，不许猜）。

**S3 复核清单**（逐条打勾并给结论）：单票 ≤10%、行业 ≤25%、ST/退市整理已剔除、止损 = 成交成本×0.85、买单全部是限价条件单、现金层（建仓弹药 + 挂单冻结留 T+0、观望资金进池）、周报数字与产物一致、计费按周期结算（第 2 步补记上一周期，本次不结算）。0 问题也要交「检查了哪些项」。

**S4 输出**：每条给「级别（A 可直接修 / B 待拍板）+ 位置（文件:行）+ 建议修法」；Lead 只执行 A 类，B 类写 `pending_changes`。

**失败兜底**：子代理超时、产物为空或 schema 校验失败 → Lead 按任务书自己做，并在汇报里写「子代理失败，Lead 代做」；不允许空结论进 `--ingest`，宁可停。

**防污染**：子代理回报里的每个数字都要带来源路径；Lead 写进周报/计划书前抽查 2–3 条。收尾时写 `out/team/decision_<日期>.md`：输入快照、各子代理结论摘要、被否理由、最终决定、遗留 B 类——下周开工先读它。

五、报告与落单

- 周报数字只能来自本轮 `out/` 产物；T9 四段：本期结论 / 策略调整 / 未来 1–3 期规划 / 计费核对（不结算）。第 3 段必须写「下周日巡检附加任务」（没有写「无」）——写成可直接粘进巡检提示词「五、本周附加任务」的话。
- 订单以 `weekly.py` 产出的 CSV 为准（卖出下一交易日开盘、买入限价条件单、一字板不撮合，见 `SKILL.md` §8.2）。
- 汇报按 `SKILL.md` §6 的中文格式；利润指标一律展示**净利润**（账户收益 − token 实花）。**不写评分、档位、奖励行**（这些只在月报出）。

六、第 10 步：收口本周技能问题（不做完，决策日不算结束）

- 逐条处理 `out/patrol_findings.md` 的 A 类遗留项与 S4 的 A 类建议：修好 → `selftest_all.py --fast` 全过（动了引擎再跑 stock 单测）→ `git commit` + `push` → 回填 `[x] 已修（commit <hash>）`。
- 本次执行中新发现的问题：A 类当场修（同上流程）；B 类（阈值/权重/仓位/预算/交易参数）只追加 `out/team/pending_changes.md` 等拍板，不许自己改。
- 更新 `HANDOVER.md` §1/§4/§10；技能定义或任务 prompt 有变化时刷新 `out/team/schedule_snapshot_latest.json`。
- 汇报末尾给「维护清单：修了什么（commit）/ 仍开放什么 / B 类待拍板」。

七、硬约束

- 决策日不取数：不跑 `run.py`（除 `--only-plan`）、`screen`、`etf`、`wealth`、`otc`，不跑 stock 脚本，不改本机计划任务。
- 数字只许来自本轮产物；拿不到就如实写原因，不许编。
- 计费口径：第 2 步 `billing.py --task-end` 补记上一周期（上次结算终点 → 现在）；**本次决策不结算**（会话没结束、算不准，留到下次第 2 步）；巡检按 0.01 元/天定额记；月报不记账，并入下一次补记。
- 子代理只做判断/只读复核，不许改 `config`、账本、脚本，不许 push。

## 本周可变部分（按需增删，写进调度器 prompt）

八、本月附加任务

来源：最近一份月报写下的 `out/team/monthly_plan.md` 里「下月决策日附加任务」那一段（**由月报安排**）。有就照抄进调度器本节；文件不存在或那一段写「无」就写「无」。

只允许三类，且都不动主干：

- 多读一个文件并报结论（如某份回测结果、某个数据源产物、某期周报）；
- 多查/多报一件事（如核对某只持仓的止损生效日、确认某数据源是否恢复）；
- 验证一个已知问题是否复现（只读 + 观察；要修就按 A 类走第 10 步）。

禁止：改 10 步顺序、放宽硬约束、跳过 doctor/preflight/ingest 校验、改账本或策略参数（B 类只写 `pending_changes`）、把附加任务变成本周的主线。需要更大动作的，单独开会话做。

**本周值：无**
