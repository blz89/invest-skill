# 月报 / 年报提示词（每月 1 日 22:00）

> 规则与阈值以 SKILL.md、references/team-framework.md §7 与 config.py 为准，本文件不抄数字。
> 用途：本文件是这条定时任务的唯一事实源——调度器 prompt 只放指针（读本文件全文执行），不内嵌正文；改本文件即生效，不动调度器。
> **同一个定时任务两种模式**：1 月 1 日跑「年报模式」（年度结算 + 年报 + 写年度计划），其余月份跑「月报模式」。先判模式，再按对应步骤走。

> 解释器约定：下文 `& $py X.py` 均指用技能 venv 跑：`$py = 'D:\skills\invest\stock\.venv\Scripts\python.exe'`（PowerShell 里先赋值再用）。

## 〇、先判模式（第一步）

- 当天是 **1 月 1 日** → **年报模式**：执行第三节 A（10 步），产出年报 + 年度结算 + `out/team/annual_plan.md`。
- 其他月份 → **月报模式**：执行第三节 B（9 步），产出月报 + 可行性判定 + `out/team/monthly_plan.md`。

两种模式共用第一、二、四、五、六、七、八节的写法和硬约束。年报模式额外拥有「写账本（年度结算）」的权限，月报模式没有。

## 一、你是谁、要交什么

**月报模式（其他月份）**：四件事，缺一不算完成。

1. **写月报**：`out/paper/monthly_<上月 YYYY-MM>.md` + `out/paper/monthly_report_<上月 YYYY-MM>.html`（四部分 + 季度进度 + 策略可行性判定 + 本年计划对齐），带毛利→净利对照与 token 实花。
2. **做复盘**：`out/team/retro.md`（T10：五层反思（L1–L5）+ L6/L7 复盘落地 + 策略复盘 + 技能优化），归因只算现金 carry / R2 carry / R3 beta，alpha 写「不可测」。
3. **修技能问题**：L7 技能优化里的 A 类当场修掉并提交，B 类写 `pending_changes` 待拍板。
4. **服从年度计划**：读 `out/team/annual_plan.md`（年报写的年度目标 / 分季检查点 / 参数冻结清单 / 每月必答 / 给月报的附加任务 / 年度复核触发条件），在月报「本年计划对齐」一节逐条回答「每月必答」；**只读，不得修改**。

**年报模式（1 月 1 日）**：四件事，缺一不算完成。

1. **年度结算**（唯一写账本的场合）：`monthly.py --month <去年>-12 --annual --ledger 50k`——先备份，奖励（评估期后 >0）从现金划出，本金重置为「年末净值 − 奖励」，`cum_index` 链式累计，记录写 `meta.annual_settlements.<年>`；同一年幂等，重渲染只加 `--no-settle`。
2. **写年报**：`out/paper/annual_<年>.md` + `out/paper/annual_report_<年>.html`（年度收益 + 总收益、月度分解、全年交易与现金、年度结算、可行性判定、选股评分体检、记分卡）。
3. **写年度计划**：`out/team/annual_plan.md`（固定 6 段，见第五节）——这是下一年每月月报的指挥文件。
4. **全年复盘 + A 类修复**：12 份月报逐月校对，T10/技能问题里 A 类当场修，B 类写 `pending_changes`。

**月报不是重新决策**：只读账本、只做归因与复盘，不建仓、不改订单。**计分只在年报做**——档位 / 奖励由每年 1 月 1 日的年报定档（`team.py --run-t8 --annual`、`review.py --annual`）；**月报只报四项口径 + 本季进度数字，不出档位、不判档**，周决策本来就不评分。口径见 `references/paper-ops.md` §8.4：**主指标 = 本季累计净收益率**（对季达标线 = 年化达标线 ÷ 4）；验收 = **加权年化净收益率**（季 50% / 年 20% / 长期 30%，各窗口折年化）；档位满 12 周才出；奖励评估期（2027-10-30）前恒 0。

## 二、开工前（只读）

- 读 `stock/data/invest/HANDOVER.md`（当前状态、上次交接）。
- 读上月 `out/paper/weekly_*.md`、`out/team/decision_*.md`（周决策结论）、`out/paper/decision_*.json`（落单快照）、`out/team/pending_changes.md`、`out/patrol_findings.md`。
- 读 `out/team/annual_plan.md`（年报对月报的指挥文件）；文件不存在 → 写「本年度无年度计划（年报未生成）」，继续。

## 三、执行顺序（严格按序号）

### A. 年报模式（1 月 1 日，10 步）

1. **不记账、不结算**（消耗由下一次周决策第 2 步 `billing.py --cycle-end` 补记；不需要开窗）
2. `doctor.py --ledger all`（NO-GO 立即停并汇报）
3. `score.py --return <账本累计收益率> --token-cost <out/budget.json 该账本累计 spent> --mdd <最大回撤>`（评估期未到时奖励显示 0 属正常）
4. `run.py --capital 50000`（**不加 --refresh**；若 1 月 1 日为周三或周六，决策日的「不取数」硬规则优先，跳过本步）
4b. `& $py cash_pool.py`（刷新全市场货基 90 天排行；这是全月唯一刷新点（首次运行/账本重置后首次接手例外），失败不阻断并标数据日）
5. `team.py --run --pipeline --ledger 50k --monthly`（生成 T10 任务书）
5b. `team.py --run-t8 --score-only --annual --ledger 50k`（**年报是唯一计分时点**：`--annual` 才出档位/奖励；`--score-only` 不覆盖 `out/team/lead_plan.md`；T10 的 L2 依赖它）
6. **先写可行性判定**：`out/team/viability_<年>.md`——五问表 + 结论三选一（继续 / 微调哪一层 / 暂停），格式见第四节第 5 条；缺文件 = 年报不算完成
7. `monthly.py --month <去年>-12 --annual --ledger 50k`（含年度结算；内部顺序 = 先动态本金收口（不注资）→ 年度结算重置本金 → 再注资 5,000 元；重渲染加 `--no-settle`）。**年报定档年化 = 先记录上月（上年 12 月）的等价年化，再取本年所有运行月份的算术平均**（跨年月份不进平均）→ `review.py --ledger 50k --strict --annual`
8. **写 `out/team/annual_plan.md`**（固定 6 段，见第五节）
9. 更新 `HANDOVER.md` §1/§3/§4/§5 → 若任务定义有变，刷新 `out/team/schedule_snapshot_latest.json`
10. 收口：T10 L7 的 A 类当场修（改代码/文档 → `selftest_all.py --fast` 全过 → commit+push → 回填 `[x]（commit <hash>）`）；B 类只写 `pending_changes`

### B. 月报模式（其他月份，9 步）

1. **不记账、不结算**（消耗由下一次周决策第 2 步补记）
2. `doctor.py --ledger all`（NO-GO 立即停并汇报）
3. `score.py --return <账本累计收益率> --token-cost <out/budget.json 该账本累计 spent> --mdd <最大回撤>`
4. `run.py --capital 50000`（**不加 --refresh**；若 1 日为周三或周六，决策日不取数优先，跳过本步（1 日为周三用当日 19:00 产物；1 日为周六用周五 19:00 产物），月报在决策任务收口后继续）
4b. `& $py cash_pool.py`（全月唯一货基排行刷新点（首次运行/账本重置后首次接手例外）；失败不阻断并标数据日）
5. `team.py --run --pipeline --ledger 50k --monthly`
   5b. `team.py --run-t8 --score-only --ledger 50k`（月报只取数字给 T10 L2，**不加 `--annual`**、不出档位）
6. `team.py --stage T10` → 任务书原文交 T10 子代理 → 收回报后 `--ingest T10`（`retro.md` 缺「策略复盘」「技能优化」两节会 fail-closed）
7. 执行 T10 的 L7 A 类（改代码/文档 → 自检 → commit+push → 回填）；B 类只写 `pending_changes`
8. **先写可行性判定**：`out/team/viability_<上月 YYYY-MM>.md`（五问 + 三选一；缺 = 月报不算完成）→ `monthly.py --month <上月 YYYY-MM> --ledger 50k`（**内部自动做动态本金收口**：上月 token 从现金出账 + 重算各月等价年化 + 注资 5,000 元并更新本金，不需要另跑脚本）→ `review.py --ledger 50k`（月报不判档，不加 `--strict`）
9. **月报不记账、不结算**（不跑 `--task-end`）→ 核对数字 → **写 `out/team/monthly_plan.md`**（模板见下文；第 1 段结论须与 `viability_<月>.md` 三选一一致，且不得越过 `annual_plan.md` 的冻结参数）→ 更新 HANDOVER → 必要时刷新调度器快照

### 9b. `out/team/monthly_plan.md` 固定模板（月报模式用）

每条都要有**触发条件 + 动作 + 依据 + 检查点**；可验证假设 ≤3 条；全文 ≤1 页；数字只取脚本产物。

1. **一句话结论**：本月策略是否继续 + 当前最大风险。
2. **下月仓位路线**：只用「若…则…」写档位、权益上限、篮子只数；禁止「视情况」「适当」。
3. **标的清单**：继续持有（T9 证伪条件是否仍成立）/ 观察（还差什么条件才进买入区）/ 剔除（哪条基本面或事件已坏）。只引用 `stage3_plan.json` 与上期 T9。
4. **现金与固收**：货基池金额与排行数据日、T+0 弹药、逆回购窗口（实际占款 ≥3 天且报价够才做）、下月长假窗口。金额取 `cash_yield_plan`。
5. **待验证假设**（≤3 条）：`- 假设：… ｜ 检查方式：… ｜ 截止：YYYY-MM-DD`。
6. **下月决策日附加任务**（给周决策「八、本月附加任务」）：≤3 条，只允许三类——①多读一个文件报结论 ②多查多报一件事 ③验证已知问题是否复现；没有写「无」。
7. **需要用户拍板的 B 类**：只列真正要用户决定的事项。

## 四、月报怎么写（四部分 + 季度进度 + 可行性判定 + 本年计划对齐，缺一不可）

1. **仓位与净值**：月初/月末净值、区间涨跌、最大回撤、与沪深300 对比、超额。
2. **收益与成本**：三层拆解（权益 / 场外 R2 / 现金层），token 实花，**毛利→净利对照**。
2c. **动态本金与月度等价年化（该节由脚本自动生成，写手只解读、不要重算）**：本月注资/累计注资/当前本金、本月实际运行天数与月收益率、本月等价年化、**本年（年初至本月）**各月等价年化的算术平均（年报定档口径；跨年月份只作参考、不进平均）、token 已从现金出账的说明；首月样本天数少要在本期说明里点出，别把几天的年化当结论。
2b. **季度进度（主指标，放在收益与成本之后）**：本季累计净收益率 vs 季达标线（年化达标线 ÷ 4）与金额目标、本季 token 实花 / 季度预算；年化只作外推脚注、不作达标判据；跨季时说明季初起算日与「自建账起」标记。
3. **交易与执行复盘**：成交价 vs 计划价、滑点、未成交/过期单、一字板卖不出的情形，逐条回查可证伪条件（L3）。
4. **经验教训与下月调整**：L4 先证据后结论；≤5 条改进项，标注 A 类（已做）/ B 类（待拍板）。
5. **策略可行性判定（五问，写 `out/team/viability_<期>.md`，脚本摘入 md/HTML）**：

   | 问 | 看什么 | 判定 |
   |---|---|---|
   | ① 样本够不够 | 周数、平仓笔数 | 不足（<12 周或 <10 笔）→ **只记观察，不调策略参数** |
   | ② 钱从哪来 | 超额拆成权益 beta / R2 carry / 现金利息；alpha 写「不可测」 | 超额主要来自利息 → 选股没贡献，不许自夸 |
   | ③ 风险预算用了吗 | 权益层实际占用 / 状态上限 | 长期半闲置 → 规则太保守还是没标的 |
   | ④ 执行偏没偏 | 成交价 vs 计划价、未成交率、费用率 | 偏 → 只调执行层（A 类），不碰策略 |
   | ⑤ 证伪条件准不准 | 上期 T9 的条件触发几次、判断对错 | 校准研究层（B 类，先回测） |

   **结论必须三选一**：`继续`（附最强反方证据）／`微调哪一层`（写清层、参数、回滚方式；策略参数须样本够 + 回测）／`暂停`（写触发条件与恢复条件）。样本不足时只允许微调执行层/现金层/文本。
6. **本年计划对齐**（`annual_plan.md` 存在时必填）：①年度目标进度（链式总收益 vs 目标区间）②冻结参数是否被触碰 ③偏差原因（执行/规则/数据）④是否触发年度复核（触发则写 `out/team/annual_review_request.md`）。

## 五、年报怎么写（仅年报模式）

1. **年度结论**：年度收益（当年净收益率）、总收益（累计，链式）、同期沪深300、超额、年内最大回撤、费用、token 实花、**净利润（当年毛利 − 当年实花）**、等价年化净收益率（= **本年各月等价年化的算术平均，年报定档用它**）、**加权年化净收益率（季 50/年 20/长期 30）**、档位、奖励（评估期前 0）。
2. **月度分解**：12 个月逐月净值、月度收益、总收益（建仓前月份写「—」，不假装 0.00%）。
3. **全年交易与现金**：逐笔成交、费用、现金层利息、权益层盈亏。
4. **年度结算**：本金 A → B 元（奖励从现金划出 X 元）；下一年收益率以剩余净值为起点，总收益按链式累计。
5. **策略可行性判定（五问）**：同第四节第 5 条，key=年。
6. **选股评分体检**：`score_panel.py --health --year <年>` 的面板覆盖/分维度 IC/五分组差/命中率；样本不足（<26 周或 <30 条）只写「维持现状」，**只记录、不许据此改分值**。
7. **记分卡（年报定档）**：T8 档位/奖励只在年报出（`--annual`）；月报只引数字、不印档位。**档位口径 = 本年各月等价年化率的算术平均**（年报时先记录上月的等价年化再取本年平均；不足 3 个月只作参考）；验收口径 = 加权年化净收益率 > 无风险线；奖励评估期（2027-10-30）前恒 0。

### 5b. `out/team/annual_plan.md` 固定模板（年报模式的指挥文件，6 段）

1. **年度目标**：净收益率区间、最大回撤上限、最小样本门槛；写「评估口径」而非保证。
2. **分季检查点 Q1–Q4**：每季末月报要核对什么、阈值多少、越界怎么办。
3. **参数冻结清单**：本年度不许月报动的参数（默认：档位比例、状态阈值、篮子只数、单票/行业上限、止损/ATR/熔断、漏斗阈值）。
4. **每月必答**（3–5 问）：月报「本年计划对齐」逐条回答。
5. **给月报的附加任务**（≤3 条）：写成可直接粘进月报提示词「八、本月附加任务」的话；只允许三类，没有写「无」。
6. **年度复核触发条件**：什么情况月报必须写 `out/team/annual_review_request.md` 请求提前复核（由用户拍板）。

**指挥关系**：annual_plan 只是文件，年报写、月报读；月报不得修改。月报越界（改冻结参数、加新标的池、放宽风控）只能写 `pending_changes` + `annual_review_request.md`，等用户拍板。

## 六、硬约束

- 月报/年报第一二节缺失不许伪造；数字只取脚本产物。
- **策略可行性判定（五问）必填**：`viability_<期>.md` 缺失或结论不是三选一 → 不算完成；样本不足时禁止调仓位与选股阈值。
- **服从年度计划**：`annual_plan.md` 存在时，「本年计划对齐」必填；冻结参数不得直接改，越界写 `pending_changes` + `annual_review_request.md`。
- L1 归因只算现金 carry / R2 carry / R3 beta，alpha 写「不可测」；L5 只动可回测层，一次一参并写回滚。
- 计费：**一律实扣**。巡检按会话开窗/收口自结；周决策第 2 步补上一周期、第 10 步补当前会话；周报单列「上周技能花费（实扣）」（`weekly.py` 的 `week_skill_cost`）；**月报/年报不记账**，消耗由下一次周决策结算时计入；不估算、不按定额。
- 奖励评估期 2027-10-30 前一律 0，写「评估期未到」。
- 月报模式只读账本；只有年报模式可写账本，且仅限年度结算。
- 选股评分体检样本不足时只能写「维持现状」，不得据此改分值。

## 七、与决策日撞车

若 1 日为周三或周六：20:30 决策优先；本任务在决策任务收口后于同一会话继续，且不重新取数。本任务不记账，消耗并入下一次决策第 2 步补记，不重复计。
